# 系统流：让奖励改变剧情

本实验只借鉴叙事机制。下述城市、人物、能力、任务均为原创；视频留待剧情事件稳定后接入。

## 两个原作观察

《亏成首富从游戏开始》首章先交代资源用途、禁止行为、收益转换及结算时点，主角随后才能制定策略。可抽取的结构是：**规则先行 → 在限制内提出计划 → 世界反馈可能偏离计划 → 按既定条件结算**。游戏应提前显示奖励及要求，Agent 不能事后改规则让行动必胜。[原作第1章，WebNovel](https://www.webnovel.com/book/14588444604278204/39160630080323258)

《大王饶命》第13章把日常互动产生的人际反应转成资源，资源又扩大后续选择，同时保留主角的社会处境。可抽取的是：**行动 → 具体人物反应 → 资源变化 → 新策略空间**。这里的设计推论是：能力成长应与关系、身份暴露、可进入地点一起影响下一段剧情。[原作第13章，WebNovel](https://www.webnovel.com/pt/book/8161510403317103/22235450025822155)

以上是从两段公开原文推导的设计建议，不声称覆盖整部小说。

## 原创都市异能六节点参考

1. **目标出现。** 玩家出生时已绑定“异常档案”系统，如今岚城末班地铁突然停电。系统发布“留下可核验的异常证据，并让目击者安全离站”。事先承诺奖励：30点额度及“残响辨识”，只能辨认近期异常残留，不能预知未来。
2. **玩家决定路线。** 调查断电源头可能错过救人时机；联系站务能获得协助但增加身份暴露；先带目击者撤离能建立信任却可能丢失物证。也接受“让同伴护送，我去拍摄”的自由方案，但须按已有同伴、时间和通行条件判断。
3. **即时结果。** 调查者找到损坏的继电器，目击者却不再信任其优先次序；求助者获得通行条件，行动进入站务记录；救人者得到口述线索，实体残留被清理。结果允许成功、部分成功或失败，人物反应须留在状态中。
4. **再作一次抉择。** 按已得信息选择补证：与目击者协商、请求保存监控，或冒险返回现场。没有证据就不能只因“我完成了”而结算；资源不足的强行施法会失败，随后仍可选择补救。
5. **兑现或失去奖励。** 两项要求各有实际事件支持才发放既定奖励一次。证据永久丢失或目击者遇险则任务失败，无奖励，并留下对应后果；世界继续推进到救援或追查失证原因。
6. **奖励开启新冲突。** 获得“残响辨识”后，可以追踪另一出口的异常痕迹，也可以保护已信任玩家的目击者，或向站务交换信息。上一轮是否留名、救人、保存证据应改变可行方案与风险，下一目标也由这些后果产生。

## 实现约束

每轮只执行玩家提交的行动及即时后果，下一路线交给玩家。Agent 写叙事并提出带事件证据的状态变动，引擎负责规则、奖励账本与存档；新任务不能创建即完成。数值只表达已发生的代价或结算，不能替代故事推进。有效进展是获得线索、改变信任、开放路线或留下损失，不是每发一句话都增加经验。
