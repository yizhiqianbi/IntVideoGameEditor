# 剧情实验的设计与验证

## 当前目标

让小说中的系统流成为可通过对话游玩的游戏：眼前事件、玩家行动、Agent 判定、具体后果、任务结算、下一处抉择。用户已选择都市异能。先保证故事的推进与一致性，视频留给后续节点演绎。

原酒馆工程保持独立。本实验使用原生网页与 Node 本机服务，不新增依赖。

## 决策

- 界面以正文、玩家行动和下一选择为主体，琥珀色系统提示和侧栏承担目标、奖励与记忆。
- Agent 判断自由行动，不能把所有输入归为五种数值按钮。引擎不再每说一句就发经验。
- 任务创建时公开条件与奖励，已存在任务才能推进，每项进度引用本轮事件。失败不给旧目标奖励；完成后的能力要带来新做法。
- 报告、隐瞒与公开证据应留下不同的身份暴露、人物态度和后续机会。状态保存的是具体事实和悬念。
- 服务端存档版本、唯一请求编号、会话并发锁和原子写入共同保护一次行动。模型失败保留原故事，明确错误。
- 每幕保存结算提案和快照；回溯恢复状态，导入按事件重放。新版存档目录独立于第一版。
- 当前正文模型使用已有配置；H3 是后续视频生成服务，不负责文字推演。

## 可核验范围

程序验证结算引用、资源范围、任务状态和存档一致性。剧情的因果语义依靠 Agent 上下文和提示，仍需真实试玩发现矛盾。自动验证与浏览器验证的结果在完成后记录。
