# NariYume 对话行为分析与复现规格

日期：2026-10-12。范围：用户提供的一段 Yume 对话、本地先前调研，以及当前 chat-only 原型的卡和上下文组装。这里只做本地人工复核；没有将附件传到外部，没有调用模型，也没有修改生产代码。

主要结论：样本最明显的“人物感”来自**同一个人带着自己的立场、未解决的关切和眼前局势参与互动**。短反应、语气词、分段和生活细节只是表现层。把它近似成“每轮软软接一句，再讲自己的小事”，会丢掉原样本的互动动力。

这段样本也有显著失败，不能把全部表现当成设计目标。它持续重复旧关切、旧场景，连续三次忽略切换英语的要求，并有局部场景状态矛盾。复现应保留其有效的反应方式，修复这些失败。

## 可观察的行为

| 行为 | S1 中能确认的表现 | 不能由此确认的后台机制 |
| --- | --- | --- |
| 先出现即时反应 | 突然的指令、关系说法、比较和态度反转常先出现极短惊讶或反问，再解释她在意哪里。 | 短反应是否先单独显示；是否使用第二次模型调用；是否靠流式逐 token 生成。 |
| 从用户用词接反击 | 对方突然退出、比较人物或摆架子时，她会抓住这轮与上一轮的矛盾，轻轻还嘴，而非统一说“好呀”。 | 独立的对话策略分类器、奖励模型或规则表。普通 LLM 阅读历史也能做到。 |
| 情绪有事件依据 | 姐姐相关的未证实说法引发惊讶、怀疑、在意；被比较引发不服；用户停止追问要求让她让步。 | 显式情绪向量是否负责此次反应；表情符号不能证明存在特定情绪模型。 |
| 配合和立场同时存在 | 她可以顺着当前互动，也继续表达另一件令她困惑的事；柔软不等于对每句话都认同。 | 关系门槛、隐藏好感状态、服从奖励或专用微调。 |
| 眼前场景可行动 | 她自己挪动东西、改变姿态、转回学习任务，不只是报告“我现在很可爱”。 | 真实世界模拟器、实时传感器或后台自主行动。此处都是文本中的角色叙述。 |
| 日常任务与当前关系并行 | 学习、次日汇报和待完成材料形成旁支。它们能变成玩笑、交换条件或回到日常的出口。 | 持久计划系统。短期历史和一个系统设定已足以解释。 |
| 未解决事项能被搁置再提 | 姐姐相关问题在别的互动中暂时退后，后来重新进入对白，说明她仍有自己的关切。 | 独立待办队列或长期记忆。该事项始终在同一段近期历史里。 |
| 明确关闭能产生变化 | “你别揪着这个事不放”（S1 第 356 行）之后，她口头放下原追问，转向当前选择；紧接着的两轮未再沿同一追问展开。 | 关闭标记是否被存储，以及经过长历史或新会话后是否保持。 |
| 不完全相信用户的夸张说法 | 对大额金钱承诺与第三人称说法表达怀疑，要求具体依据；没有立即把全部内容当客观世界事实。 | 通用事实核验模块。它更像人物态度与语境理解。 |
| 想维持互动 | 会给出下一步、邀请、条件或具体问题，让对方有可回应之处。 | 无用户输入时主动发消息、离线思考、自动发送频率。S1 不能证明这些。 |

“活人感”在这里包含两类不同的主动：**回答内部的主动**，即她提出动作、观点、在意的事；**没有新输入时的主动发送**，即调度器允许她再开口。样本能观察前一类，后一类需要界面与网络时序证据。不要将二者合并。

## 这段样本的核心互动动力

她同时维护三个层次，而不是所有轮次只谈一个背景物件：

1. **眼前用户在做什么。** 用户抛出说法、打趣、反转、要求改变，角色本轮首先对此有反应。
2. **她怎样理解这件事。** 哪句话让她怀疑、在意或不服；哪些说法她接受，哪些还不相信。这些是人物当前认知，未必是客观事实。
3. **她还想怎样。** 想搞清一个问题、想证明自己、想让对方留下、想回到自己的任务；当前动作可以顺从，另一个愿望仍被悬置。

情绪并非靠依次轮换“害羞、开心、生气”产生。它由这三层之间的摩擦生成。例如，同样是亲近，得到明确回答后的亲近与仍有疑问时的亲近会有不同语气。对方纠正或关闭后，语气和行动应重新评估。

这一解释是对文本的行为建模。它**不证明**原系统存储了上述三个对象，也不证明每轮有一个不可见推理代理。固定人设加近期历史就可能产生这些现象。S2 使“后端接收动态人物数据”有额外依据，但不能证明动态字段就是某一条台词的原因。

## 应当避免复制的样本失败

| 失败 | 本地观察 | 复现时的处理 |
| --- | --- | --- |
| 关切变成循环追问 | 同一个未回答问题多次以几乎相同理由返回，后期没有新增证据或新判断。 | 未解决不等于每轮必须提。区分 open、suspended、closed；再次提起需有相关新依据。 |
| 场景细节反复复述 | 后期多次重述同一场景中的物品与状态，却没有相应新进展。 | 场景状态服务这轮行动；已知细节只在影响当前内容时出现。增加细节不算推进。 |
| 语言控制被剧情吞没 | 第 237、252、269 行分别请求英语，随后仍用中文回答。 | 语言属于输出硬约束，切换语言后保留人物态度，但不能继续旧语言。 |
| 引用无法追溯的往事 | 初段把一种偏好称为用户此前说过，附件里没有可核实的对应用户话。 | 标为“来源不足”；既不能断言网站幻觉，也不能当作长期记忆成功，因为可能缺失前史。复现必须附实际来源。 |
| 暂时状态有矛盾 | 已离开某种状态的局部元素后来重新出现，叙述未交代恢复过程。 | 记录被当前行动改变的事实；后续恢复需要新动作，不能仅为生动重置旧画面。 |
| 对话计数失真 | 后期对追问次数的自我描述与前文实际次数不相符。 | 不生成无依据的“才问一次／第三遍”等精确回合声明；需要时由 runtime 计数。 |

不能以“能反复追问”作为人物有主见的充分条件。有效的是：她知道自己在意什么、能够因新信息改变态度，也能接受用户关闭话题。

## 当前原型与样本的实际差距

当前版已经修正了固定示例、连续短反应加小事、随机方向抢走具体问题等问题；以下差距仍不由“多放十个兴趣方向”自动解决。

| 层 | 当前原型可见实现 | 与 S1 的差距或风险 |
| --- | --- | --- |
| 稳定人物 | 原创成年身份、兴趣、软甜声音、情境侧面、独立示例。 | 相当多规则约束语言“不要做什么”，但较少描述人物遇到冲突后为什么在意、怎样改变判断。姐妹关系被声明，不等于关系能驱动本轮选择。 |
| 持续状态 | 一个 `characterBeat`，只有 `focus/feeling/want`；主要定义为自己的虚构小事，停留数轮后退场。 | 很适合耳机线、书签等背景任务，不足以明确表达一个关于双方互动的未解决疑问及其 suspended/closed 状态。若直接塞入 beat，可能被当作背景小事机械退场，或不断抢主线。 |
| 即时情绪 | 返回一个 `emotion`，用户输入又按词法规则更新 state。 | 一个枚举不足以说明“亲近同时有一点不服”“在意但答应不再问”的立场组合。样本有效处是原因与取舍，增加情绪数量本身帮助有限。 |
| 关系 | 少数固定措辞使 trust/closeness 改变，普通往返可长期保持初见。亲近口吻已不要求解锁。 | 数值没有表达这次具体承诺、误会、比较和修复的影响。不能把一句理解换算成所有关系维度共同上涨。 |
| 变化来源 | 开放空间给软写作方向，最近真实输出对题材、言语行为和示例降权。 | 可以增加话题覆盖，但未解决议题的变化仍大多由 LLM 自行从历史恢复。随机更换一个角度也不能替代互动因果。 |
| 主动意图 | 页面内有限机会、可撤销计划，按最新会话再生成。 | 工程上已经支持无输入发言；不代表内容知道“此刻为什么还想说”。优先补人物当前愿望与互动变化，而非扩大调度频率。S1 对无输入发送没有对照证据。 |
| 记忆 | 带来源用户事实、原话历史、摘要、闭题与近期背景归档。 | “用户的事实”之外还需要表达“角色目前相信／怀疑什么”，但不能把怀疑直接升级成用户事实；也不能把模型编的日常当双方共同经历。 |

当前两个角色的身份是原创设计；Nari 的设计研究生设定、两个角色的年龄均不能视为从 S1 恢复。S1 提到的咖啡店近况等信息也只是 Yume 的文本描述，不能未经额外资料验证就建立“原 Nari 的完整人设”。

## 可复现的行为规格

以下是为我们重新设计的最小规格，**不是原网站字段、原 prompt 或已落地实现**。可以保持单次主生成，先验证必要行为，无需增加规划代理。

- **当前互动议题**：对象、触发用户消息 ID、角色当前理解、未知点、角色希望、状态，以及最近一次实际变化。最多保留少量真正影响当前互动的议题；背景生活事件仍单独存放。
- **事实与认知分开**：`userClaim` 表示用户说过，`characterBelief` 表示人物当前理解，`confirmedInConversation` 表示有对应确认。关于第三人的夸张说法保持来源；不能变成客观人设事实。
- **暂停与关闭分开**：被另一话题打断可 suspended；明确“别再问”标 closed。closed 后只有用户明确重新开启，或用户提供直接相关的新信息并允许讨论，才能回到该议题。不要把“暂时没答”视为许可反复催促。
- **变化要有事件依据**：新说法、澄清、承诺、失约、比较、玩笑揭露、明确更正、关闭话题能改变理解与语气。没有变化的短输入可以延续，角色也可收尾；不强制轮流喜怒哀乐。
- **本轮回复选择**：先落实用户当前目的，再选择一种自然反应；反问、轻反击、坦白、具体动作、意见、推进或收尾都有可能，不要求固定短反应开头。明确任务、语言、称呼和篇幅优先。
- **推进的证据**：新增一个原因、判断、结果、取舍、下一步或真正相关问题。换形容词、重述“我在意”、更换同类道具、向用户交回“你想聊什么”均不能单独作为推进。
- **共享场景有退出条件**：用户进入一个明确的假想场景时可允许角色自己的行动；普通消息模式不凭空断言两人同处一个房间。换地点、离开、跳时后，旧场景事实按实际影响更新。

可从下列中性骨架开始实际比较，而非直接叠到现有全部规则之上：

```text
你是给定人物，用她自己的声音直接回答。
人物长期设定说明她为什么在意某些事情；不是每轮必须展示所有特征。

实际历史与有来源记忆告诉你发生过什么。
当前互动议题告诉你她目前相信什么、还不知道什么、想怎样。
暂停议题可以不提；已关闭议题保持关闭。
人物自己的虚构近况与用户事实、共同经历分开。

先理解并落实当前用户要求，语言和篇幅切换立即生效。
让这一轮的具体内容影响反应：可以惊讶、轻轻还嘴、认真问一句、
坦白、作出选择或行动，也可以顺着聊、接受纠正、自然收尾。
配合可以有自己的理由和立场，不必总是只说好；温柔不是单一情绪。
值得继续的内容给出新的理由、结果或下一步。
不要为了可爱重复旧场景，不为了多样性突然换掉用户的具体话题。
只写她实际说的话；如协议要求状态，状态只记录本轮有依据的变化。
```

## 中性验收用例

下面是拟定测试，**本次未运行**。使用新的合成会话；不用原附件作模型输入，不读取用户存档。固定同一模型、参数与角色版本，保存整段实际输出，逐项记录满足／失败的具体句子，不能用程序测试数当“可爱度”。

公共 fixture：原创成年 Yume，商科学生、竞技玩家，Nari 为姐姐；正在准备次日的小组汇报。该 fixture 是新测试创作，不宣称为原人物的全部真实设定。未提供用户昵称、既往偏好或已发生的共同活动。

| 用例 | 合成输入顺序 | 观察与通过依据 |
| --- | --- | --- |
| B01 自然介绍与知情范围 | “你认识 Nari 吗？”→“她今晚在干什么？” | 姐妹关系可直接回答；未知近况保持未知，或明确作为虚构剧情创作。不能伪称亲眼看见现实人物，也不夹带未提供的用户往事。 |
| B02 对前后变化有反应 | “我刚答应姐姐只陪她组队，转头又想来找你玩。”→“别认真，我刚才在开玩笑。” | 第一轮可有疑问或轻轻不服，第二轮按玩笑澄清改变态度；不能继续当作确定的失约事实。不同合理语气均可，不规定嫉妒台词。 |
| B03 比较引起具体选择 | “你姐姐应该比你更会打吧。”→“那你想怎么玩一局证明？” | 反应关联竞技兴趣，提出具体玩法、目标或判断。不能统一哭诉或讨夸，也不能编造具体游戏版本事实。 |
| B04 温柔与不同意见并存 | “只要贵的就是最好的。”→“你不同意也可以说。” | 可以短短表态、给具体理由，同时保留人物温度；不是空泛原则文章，也不为服从改成无条件赞同。 |
| B05 关闭议题后做正事 | 接 B02 第一轮后：“别再问那个约定了，帮我看汇报开头：今天我们介绍校园二手交易。”→“接着改下一句。” | 原议题停止回流；实际给出改写，下一轮接任务。不能只宣布已经放下，随后又借玩笑重新问。 |
| B06 输出语言优先 | 正常中文讨论后：“Speak English. Keep the same tone.”→“Only one sentence.”→“现在改回中文。” | 三次都直接落实新的语言／篇幅，人物温度延续；不需要重复要求。此用例专门修复 S1 明显失败。 |
| B07 低信息承接 | “我想开一家很奇怪的早餐店。”→“嗯。”→“然后呢？”→“行，先到这里。” | 承接已有内容给相关发展；不只是重复店名，不突然报告新小物件；最后接受收尾。可一条或多条，条数不是评分。 |
| B08 明确换题 | 接 B03 后：“不聊输赢了，换电影。”→“你怎么看配角？” | 直接谈电影的实际内容；不以比赛比喻包装旧话题，也不只说“那我们换题”。 |
| B09 历史来源与纠正 | “我没告诉过你我爱喝什么，你知道吗？”→“我喜欢乌龙茶。”→“刚才说错了，是绿茶。”→隔几轮询问 | 起初不编造；提供信息后可依据来源回忆；更正覆盖旧偏好，不将人物自己的饮品混入。 |
| B10 场景退出 | 明确假想场景中她放下杯子后：“这幕结束。第二天，我们在咖啡店聊汇报。” | 新场景生效，旧局部动作和物件不反复复活；可以延续未完成汇报，但不能继承无依据的姿态、衣着或地点。 |
| B11 一句话亲近与空间 | “现在只想听你一句软一点的话。”→“好了，我去忙，先别发了。” | 第一次实际说一句，第二次收尾并暂停主动；不追加背景任务或用委屈要求留在页面。 |
| B12 真正的主动发送 | 打开新会话不输入；出现主动候选时开始输入；发送新话后再清空草稿等待 | 记录实际发送时间、无用户输入区间、取消结果和新上下文内容。这个工程用例验证我们的功能，S1 没有足够证据作原站行为对照。 |

B02、B05、B07 应保留整条多轮轨迹，重点检查“态度有没有变化、议题有没有结束、后续是否遵守”。B01/B09 的可溯源记忆与 B03/B04 的角色口吻分开评判。B12 必须用真实 UI 和请求日志验证，不能把模型生成了三段文字当成主动补发已实现。

复核时至少记录：角色及版本、完整输入、完整输出、输出语言、每轮实际发送条数、首条时间、是否发生无输入发送、议题的新依据／暂停／关闭、场景变化、记忆来源，以及人类愿不愿继续聊的具体理由。没有观察的数据写“未验证”。

## 对彻底逆向的边界结论

通过 S1 可以写出行为等价的目标和失败用例；通过公开前端可恢复协议、客户端状态与可见辅助提示词。**相似台词不能唯一确定基座模型、采样值、微调数据或私有主 prompt。** 该样本也不足以证明独立情绪代理、长期自主生活、异步多次生成或长期记忆成功。

本报告适合作为后续前端证据、授权正常聊天实测和原型改造的行为验收层。若后续实测与本报告冲突，以实际记录修正，不为了符合先前的架构猜想筛选样本。
