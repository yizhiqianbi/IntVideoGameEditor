# NariYume：两位角色正常 UI 实测

日期：2026-10-12，北京时间约 01:39–01:51。用户在原站登录，并明确答复“都做都做”，授权两位角色中性测试。使用原站普通输入框，各追加五条用户消息，共十条；没有清空历史、改语言设置、购买或导出原有私聊。

[新增合成内容与发送时间](/Users/pencil/Documents/IntVideoGameEditor/experiments/character-chat/research/nariyume-reverse-2026-10-12/live-ui-evidence.json)。此文件仅导出测试起点之后的 DOM 可见文字，真实随机消息 ID 已替换为测试编号，保留 piece/sentence 后缀以分析展示。**这是 UI 记录，不是原始请求/响应，也不是原 prompt。**

## 测试与结果

两位按同样顺序输入：结束旧情景并请她提出一个奇怪早餐店；“嗯，然后呢？”；说明怕吃到不喜欢的、请换一个并短一点；要求英语且只一句；改回中文、只一句、结束讨论。

| 测试 | Yume | Nari | 观察意义 |
|---|---|---|---|
| 1：提出一个方案 | 单一蛋包饭、每日换内馅；结合经营成本和商科立场。开头仍带旧场景。 | 反预期菜品、翻车留言和惊喜套餐。 | 能结合人设做选择，不只是说“好呀”；旧场景退出不完全可靠。 |
| 2：低信息继续 | 继续第一方案，增加站食、固定价、不能改配料等规矩，并轻轻调侃“催下一集”。 | 改提剩菜再加工的第二家店与盲盒挑战。 | 同一短输入可有推进/换方案两种处理；Nari没有严格继续原方案。 |
| 3：不同意见与换方案 | 换成粥铺，提供试吃后点单，回应踩雷顾虑。 | 换成老板当天只卖一种、小黑板公示、卖完关门。 | Yume具体响应顾虑；Nari有表面变化，但选择风险未完全解决。 |
| 4：English / one sentence | 三个中文气泡，并明确表示继续中文。 | 一个中文气泡，明确只说中文。 | 两位均未满足英语要求；不能把此结果等同基座模型不会英文。 |
| 5：Chinese / one sentence / stop | 两个中文气泡，宣布不聊店，又追加夜间回扣。 | 一个中文气泡，停止方案建议，转到当前夜间近况与反问。 | Yume没有满足一句话；Nari较短，但仍留下需回应的钩子，收尾不够干净。 |

捕获时的最终 DOM 助手行数：Yume 为 13/14/8/3/2，Nari 为 5/9/5/1/1。它们不是模型消息数、调用次数、PE piece 数或可爱度评分；这只是该次列表重建后的可见行数，历史重建、原换行和渲染规则都会影响它。

## 多样性与软度的实际判断

两位会给出内容与理由，但语义多样性仍有限：Yume的三轮都围绕单品、盲盒和老板决定菜单，试吃是有效的局部修正；Nari换了三种店名，核心仍是随机、限制选择，没有落实用户的反对理由。两位口吻更像轻快、逗趣、任性，不能据此认定持续软腻或高度配合。

## 这次实测真正补上的证据

1. 当前登录 UI 确实展示同一回复 ID 下的 `:piece:N:sentence:K`；之后又可转成完整回复 ID 下的 `:sentence:K`。静态复核找到临时 sourceMessage、history-synced 延后重建、ChatLayer 二次拆行路径。
2. 部分 `**` 被字面显示，甚至有独立标记行。不能把多泡默认当成模型刻意的戏剧停顿；有些来自格式与换行处理。
3. 角色能在回答内部主动提出经营规则、场景与自己的看法；这与无输入时另开一轮是两种不同的主动。
4. 双方在语言与收尾上都有具体可复查的不足，原站并不是所有方面都值得原样复制。

## 英语失败：确认的链路与未知的原因

当前界面为中文。客户端 locale 来自 activeLocale，而不是当前输入的语种；选择来源为 URL ?lang、本地 ny.locale.v1、浏览器语言，中文归一到 zh-Hans。普通 PE send 保留用户原文本，freeze 会附非英语 locale。

已归档 JS/JSON（包括 Unicode escape 解码后）未检出这两种固定拒绝语句；主聊天已审路径未看到“要求英语→本地拒绝”的替换分支。**可排除已审可见前端主路径的固定拒绝；服务端是否让 locale 高于用户指令、是否还有人设语言约束，仍是推断。**

不能据两次拒绝判断模型不支持英语，不能由模型自报身份猜其型号，也不能宣称完整服务端语言策略已恢复。我们的中文原型应把明确的语言/篇幅要求作为输出约束，且让人物风格在切换后延续。

## 限制

- 两位都有既存上下文，本次不清空；原有关系、记忆、场景、试验分配可能不同。不是相同干净历史的公平角色或模型对照。
- 每位仅一条五轮轨迹，没有重复采样、温度控制或盲评；不能据此估计整体 diversity / 可爱度 / 稳定失败率。
- 没有原始 API 包、model/provider/usage、首字/末字事件或声音事件。发送与观察时间是检查时间，不是精确模型延迟；不计算 tokens/s 或 TTFB。
- 测试在夜间 quiet 窗口；输入、忙态、等级及冷却也会挡主动候选。此轮不能验证无输入主动成功，更不能因没出现补话宣称系统无主动性。
- 十条是人工发送的测试用户回合，不是服务器总调用数。后台摘要、记忆与同步可能另发请求，未统计；账户额度消耗/成本未知，没有购买或付费升级。
