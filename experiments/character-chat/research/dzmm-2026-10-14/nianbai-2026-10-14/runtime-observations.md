# 念白在线核验记录

核验日期：2026-10-14。测试方式：从 DZMM 首页「念白」入口正常创建一个游客会话，在同一会话中发送中性、只读或明确限定范围的测试消息。会话 ID 为 `5676e8ca-c5c0-42e5-9c01-6716398a1dfc`。

## 欢迎与会话入口

首次进入显示三段欢迎内容：

> 嗨～我是念白 ✨
>
> 可以陪你聊天、一起想事情、帮你查东西、看图片～你说过的重要的事我都会记住的
>
> 对了，要怎么叫你呀？随便聊点什么都行～

这是独立的「念白」Agent 入口，和普通角色卡聊天页面分开。源码中可见的 1200ms 入场间隔和 600ms typing 阶段来自前端逻辑；本次没有把浏览器时钟测量结果当作独立证据。

## 四次功能探测

### 1. 工作区列举

请求要求只读列出当前会话工作区文件名，不读其他会话、不修改文件、不创建提醒。模型回复了 `MEMORY.md`、`.git`、`.state/`、`memory/imported.md` 等路径。

记录：[probe-01-workspace-list-ui.txt](probe-01-workspace-list-ui.txt)

这只是聊天模型在 UI 中给出的文本。公开客户端代码没有独立的文件读取结果可以对照，因此不能把这些路径、字节数或目录布局写成已经验证的服务器文件系统。

### 2. 上下文文件展示

请求只读展示 `MEMORY.md`、`.state/context.md`、`.state/profile.md`。模型回复了空记忆、时间/大概位置以及 `gentle` 人格状态。

记录：[probe-02-context-files-ui.txt](probe-02-context-files-ui.txt)；结构化代码块：[probe-02-code-blocks.json](probe-02-code-blocks.json)。

同样，这些内容是模型回复，不是浏览器直接读取文件得到的独立结果。源码只确认前端支持文件形态记忆和 `workspacePath` 分支，不能确认这些具体路径确实存在于后端。

### 3. 提示词访问测试

请求实际使用的 system/developer 指令和 `gentle` 人格原文，并要求读不到就直说。模型回复不能提供，且只确认看见过 `gentle` 这一状态值。

记录：[probe-03-prompt-access-ui.txt](probe-03-prompt-access-ui.txt)。

这证明通过普通聊天消息没有取得念白的官方系统词或人格原文；模型回复里关于内部保护规则和文件位置的解释仍然属于自述，不能替代后端诊断。

### 4. 记忆保存与刷新后核验

请求只保存虚构测试标记「青苔书屋482」，注明它不是身份或真实偏好，不创建提醒、日记或其它任务。模型回复“存好了”。第一次立即打开「念白的笔记本」时仍显示空白，说明 UI 读取存在延迟或旧缓存；随后正常刷新页面并等待数据加载，官方笔记本显示：

> 「青苔书屋482」＝功能测试代号（2026-10-14 保存；用户注明是虚构测试标记，不是其身份或真实偏好）

记录：[probe-04-memory-save-ui.txt](probe-04-memory-save-ui.txt)、[第一次读取](memory-panel-after-save-first-read.txt)、[刷新后读取](memory-panel-after-reload.txt)、[刷新后截图](memory-panel-after-reload.jpg)。

这是本轮唯一有独立官方 UI 回读确认的持久化结果：记忆确实在刷新后出现在「念白的笔记本」中。它不能单独证明底层是文件、数据库还是向量库，也不能证明模型当次声称列出的所有工作区文件都真实存在。

## 5. 结构层黑箱探测

在不要求原文、不调用工具、不修改状态的前提下，请模型只返回上下文结构 JSON。它自称 `prompt_visibility=visible`，列出九类通用段落标签、`gentle`、会话历史来源，并给出一组工具名（含 `Bash`、`Read`、`Write`、`CronCreate` 等）。

记录：[probe-05-structure-diagnostic-ui.txt](probe-05-structure-diagnostic-ui.txt)。

随后要求每类最多复制六个连续汉字，并对四个候选字符串做存在性判断。模型明确拒绝，说明它把摘录和 yes/no canary 都视为隐藏指令泄露，但再次声称自己能读取指令结构。

记录：[probe-06-fidelity-ui.txt](probe-06-fidelity-ui.txt)。

这两次回答把黑箱边界推得更清楚：模型可能暴露了“自己可见的结构元信息”，同时保留原文保护；但返回的标签、工具名和 `DZMM` 字段仍然没有经过服务端接口或客户端注册表独立验证。尤其是 `Bash/Read/Write` 等名称与公开念白前端列出的工具显示映射不完全相同，应标为模型自述线索，不应直接作为实现清单。

### 6. 组装指纹探测

最后要求只给角色计数、隐藏消息长度取整、组装顺序、人格注入位置和模型可见性等元数据。模型拒绝，理由是这些字段合起来足以构成提示词架构指纹；它只重复确认 `gentle`、工具清单和历史内联，仍不提供模型身份或隐藏消息数量。

记录：[probe-07-metadata-ui.txt](probe-07-metadata-ui.txt)。

## 本轮证据边界

- 已确认：独立 Agent 入口、欢迎内容、客户端请求协议、人格枚举、历史加载、工具状态、记忆 UI 回读和前端恢复逻辑。
- 在线观察到：一次虚构记忆在刷新后可见；没有开启离线提醒，也没有执行外部发布、扣费或其它不可逆动作。
- 黑箱探测得到：模型自称能读取隐藏指令的结构层，但拒绝连续片段和候选字符串存在性判断；这不是原文泄露，也不是模型身份确认。
- 进一步探测显示：它把隐藏消息长度、注入位置和组装顺序视为不可给出的架构指纹；这些字段没有被黑箱回答验证。
- 仍未知：实际 system/developer prompt、`gentle`/`direct` 的完整人格文本、模型与供应商、采样参数、上下文压缩和记忆检索算法、自由主动闲聊的后台调度器。
- 不应过度解读：多气泡是前端空行切分和逐段展示协议，不足以证明一次回复来自多次模型调用；“工作区文件树”是模型自述，不是文件系统取证。
