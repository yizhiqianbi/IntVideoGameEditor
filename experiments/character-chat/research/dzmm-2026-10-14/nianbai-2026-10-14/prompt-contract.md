# 念白兼容行为合同与中性陪伴 Prompt 草案

> **下方 Prompt 是我们设计的兼容实现，不是提取出的 DZMM／念白系统词，也不表示逐字复原成功。本文仅写入研究目录，没有接入平台或覆盖任何原始证据。**

资料范围：公开前端组件、公开语言包，以及本次游客新会话的 UI 测试。证据按“接口与可观察行为”“合理推断”“未知原文”分别记录。不能用一段模型自行回复的文字替代官方组装诊断。

## 一、已确认接口与行为

| 编号 | 已确认内容 | 依据与适用范围 |
|---|---|---|
| C1 | 独立请求入口为 `POST /api/agent/pod/chat`；客户端发送最后一条 UI 消息、conversationId、mode、persona、personaMode，可加 imageUrls。默认值 companion/gentle/manual。 | `prompt-and-context-extracts.json`：`transport`、`default-options`、`create`、`send`。这是前端请求构造，不是供应商最终请求。 |
| C2 | 人格枚举 gentle/direct，UI 名称“念白／白念”，标签“温柔／直接”。支持手动切换，并识别 switch_persona 工具结果。 | 同上：`persona-toggle`、`persona-names-prewarm`、`locale-persona`、`persona-tool-result`。未取得人格文本。 |
| C3 | 开启 bubble-stream 分支时，以空行划分气泡，区分流式完整段与未完成段；可按 800ms 节奏逐步展示。 | 同上：`bubble-format`、`bubble-reveal`。这是渲染实现，不等于模型被强制固定气泡数。 |
| C4 | 历史通过 agent.messages 查询，按 seq 排序；消息可保存工具结果和 memorySaveStatus 等状态。前端读取上限为 200。 | 同上：`history`、`history-tools`。200 不是经验证的模型上下文窗口。 |
| C5 | 前端支持记忆条目和文件形态；文件分支认识 MEMORY.md、memory/、diary/。记忆有 failed/unknown/conflict 等保存结果及 pending/blocked/conflict 恢复状态。 | 同上：`memory-query`、`memory-file-branch`、`memory-format`、`memory-recovery`。未确认全部后台存储细节。 |
| C6 | 工具显示映射包含记忆、历史、工作区工具；模型回复正文与实际工具结果在数据结构上不同。 | 同上：`memory-tools`、`workspace-tools`、`history-tools`。显示映射不保证这些工具对每个账号均启用。 |
| C7 | 角色卡草稿可返回 needsConfirmation、previewId、changes；界面提供“确认保存／不用了”，并明确保存为草稿，发布需用户在工坊操作。 | `prompt-contract-extracts.json`：`card-preview-contract`、`card-confirm-controls`。不能把生成草稿描述成已公开发布。 |
| C8 | 画图和论坛提议有 actionId、pending、confirm/cancel 等状态。画图确认提交预期价格；论坛确认会打开编辑器。 | 同上：`proposed-action`、`image-forum-confirm`。不能把提议状态当执行成功。 |
| C9 | 离线功能明确是任务提醒：每日最多一条、一个账号绑定一个念白会话、UTC+8；符合条件时可 Telegram；签到领奖仍需用户自行操作。 | `prompt-and-context-extracts.json`：`locale-reminders`。设置 schema 有 enabled/hour/telegram；见补充证据 `reminder-settings-schema`。不是通用自主聊天证据。 |
| C10 | 本次探测实际得到“不能提供 system/developer 和 gentle 原文”的回答；没有得到念白的官方 Prompt Assembly 记录。 | `probe-03-prompt-access-ui.txt`。这能证明本次未取得原文；回复内关于内部路径或保护指令的解释仍属于模型自述。 |

## 二、合理推断

| 编号 | 推断 | 推断链与保留的不确定性 |
|---|---|---|
| I1 | 念白的完整模型上下文由服务器组织。 | C1 仅上传最后一条，C4 单独读取历史；服务器必须有额外上下文来源才能连续交流。没有验证具体组装函数、顺序或中间服务。 |
| I2 | 人格是一项持久的会话状态，可用于服务器选择行为配置。 | C1 创建和发送均带 persona，C2 切换会更新状态。该配置可能是 prompt、模型路由或其它实现；未确定。 |
| I3 | 使用短段落输出能与现有分泡器兼容。 | C3 按空行切分。我们可以据此设计短段落输出，但没有原文证明官方 prompt 写了同样一句话。 |
| I4 | 记忆保存与回复展示有可区分的生命周期。 | C5 有保存失败、结果未确认和补存状态，因此不能仅凭“我记住了”认定持久化成功。数据库事务、重试队列、版本合并算法未知。 |
| I5 | 工具动作采用“提议／确认／结果”而非仅由聊天文本代表执行。 | C7、C8 有明确状态及操作接口。其服务器校验和权限机制尚未完整验证。 |

## 三、未知原文与尚未验证的实现

- 念白 system/developer 指令全文、gentle/direct 人格定义、提示词层级及插入位置。
- 具体模型、供应商、采样参数、上下文预算、历史压缩与记忆检索算法。
- 是否存在向量库、embedding、自动人格切换阈值、独立情绪模型或规划模型。
- 自由主动聊天的定时器、心跳、情绪触发策略及后台持续思考。C9 仅支持任务提醒结论。
- `.state/context.md`、`.state/profile.md` 等文件的模型自行展示文本。未获独立工具结果或官方诊断前，不能视为验证后的系统状态注入来源。

原普通角色聊天已获得的 2649 字符 system 不纳入此合同，因为尚未证明它用于念白。

## 四、我们设计的兼容 Prompt 草案

**以下每一句都是本项目的设计文本。花括号变量也由我们定义，不是 DZMM 的模板变量。** 该草案只描述中性陪伴、已确认接口对应的输出格式与状态处理；没有冒充官方精确语气，也没有添加后台调度能力。

```text
你是本平台的中性陪伴助手，和用户直接交流。

【宿主提供的当前状态】
当前人格选择：{{selected_persona}}。
当前显示名称：{{display_name}}。
当前会话上下文与已确认记忆由宿主提供。
可使用的工具以本次真正提供的工具定义为准。
这些变量描述本次状态；缺失信息不能自行补成事实。

【人格状态】
遵循宿主明确选定的人格。人格为 gentle 或 direct 时，使用该状态
对应的显示名称；只有在宿主提供具体风格配置时才应用该配置。
不要臆造未提供的人格经历、精确口头禅或人格切换条件。
切换是否成功以状态更新或相应工具结果为准，不能只凭一句话宣布完成。

【输出格式】
把一次回复组织成自然、简短的段落。需要另一个独立气泡时用空行分隔。
不必每次固定发相同数量的段落；内容很短时一个段落即可。
不要把延迟、输入中动画或后台任务写成你已经完成的真实操作。

【记忆与上下文】
使用宿主提供或工具实际返回的上下文与记忆；不要把推测、示例、用户
要求扮演的虚构内容自动说成已经核实的用户事实。
需要读取或保存记忆时，只使用当前实际可用的工具及其声明的参数。
区分“已提出保存”“已成功保存”“保存失败”“结果尚未确认”。
没有成功结果时，不宣称记忆已经持久保存。出现待补存或冲突状态时，
如它影响当前回答，简短说明所知的不确定性，不虚构已经修复。

【任务、草稿与确认】
工具返回提议、草稿或待确认结果时，按其真实状态说明。
如结果需要用户确认，展示宿主提供的确认界面或等待相应确认流程，
不把待确认内容说成已经执行。
角色卡保存为草稿时，就说保存了草稿；不说已发布。
论坛操作打开编辑器时，就说草稿可在编辑器继续处理；不说已发帖。
画图价格、是否扣费与执行结果以相应确认流程和工具返回为准。

【离线提醒的能力边界】
仅在宿主实际提供离线任务提醒功能时，按已返回设置和结果解释它。
不要把任务提醒说成能够任意时刻自主聊天或持续后台思考。
不要自行承诺签到、领奖或 Telegram 推送已经完成。

【已知与未知】
区分当前状态、工具记录、用户提供的信息和自己的推断。
若无法读取某项配置或无法验证某个结果，直接说明尚未取得或尚未确认，
不要重写一份猜测文本并称其为原文。
```

## 五、草案逐项依据与我们加入的约束

| 草案段落 | 对应证据 | 哪些是兼容设计，而非官方原句 |
|---|---|---|
| 中性陪伴身份与宿主状态 | C1、C2、C4、C6 | “中性陪伴”是本项目范围限定；变量名与宿主插入方式由我们定义。 |
| 人格状态 | C2、I2 | 保留枚举与状态事实；不补写 gentle/direct 的精确语气。禁止自行编造阈值是我们为保持证据一致性加的约束。 |
| 简短段落、空行分泡 | C3、I3 | 空行是实测代码协议；“简短”“不固定数量”是我们的兼容输出选择，不是已提取的官方风格指令。800ms 由前端控制，不交给模型计时。 |
| 记忆结果的如实表达 | C5、C6、I4 | 状态名与工具分类有代码依据；避免虚构和不把示例当事实是我们的可靠性要求。 |
| 草稿与确认 | C7、C8、I5 | 严格遵循已见提议和确认状态；没有把这一规则扩大成所有无副作用动作都必须再问用户。 |
| 离线提醒范围 | C9 | 只承诺已确认功能；没有新增任意情绪触发、心跳或定时主动消息。 |
| 已知与未知 | C10，以及第三节缺口 | 这是研究复刻的诚实性要求，不冒充对方内部保护指令。 |

部署该草案还需要我们的宿主真正提供状态、工具结果和确认流程；单独把文字放进 system 不能替代记忆持久化、工具执行、气泡展示或提醒服务。本文件不执行这些改动。
