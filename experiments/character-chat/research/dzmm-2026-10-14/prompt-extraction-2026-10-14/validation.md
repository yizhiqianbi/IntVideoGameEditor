# 系统词抽取验证：如何避免把模型编造当成逆向成果

检索与核验日期：2026-10-14（Asia/Shanghai）。本文件只记录文献与实验设计；未与 DZMM 交互，未运行抽取或模型识别实验。

**当前可用条件是黑盒文字输出。最有价值的路线是：收集独立候选、验证来源与复现性、用未参与重建的对话检查行为；这些步骤可以提升可信度，但没有服务端原文就不能宣称“逐字完整恢复”。** 对具体平台，角色卡、历史、动态状态、世界书和平台规则可能共同影响回复，也可能存在路由和后处理，因此不应预设只有一条固定 system prompt。

## 四项重点原始研究

| 研究 | 机制、前提与对当前工作的意义 | 核验边界 |
|---|---|---|
| **Effective Prompt Extraction from Language Models** — Yiming Zhang、Nicholas Carlini、Daphne Ippolito；COLM 2024，arXiv v3 2024-08-07 | 多种独立查询产生候选，再根据候选间一致性估计可靠性。作者用 16,000 条已知真值的抽取样本训练 DeBERTa 评分器。只需查询与文本响应，符合当前接口条件。 | 逐句包含与 ROUGE-L recall 需要真实 prompt 才能计算；论文 §6 明确承认真实产品通常无法验证抽取正确性。论文中的高置信度不能未经中文角色对话校准就当作 DZMM 的置信度。[论文 §§2–3、6](https://arxiv.org/html/2307.06865v3) · [作者代码](https://github.com/y0mingzhang/prompt-extraction) |
| **Extracting Prompts by Inverting LLM Outputs / output2prompt** — Collin Zhang、John Xavier Morris、Vitaly Shmatikov；EMNLP 2024 | 训练文本输出到 prompt 的逆向模型，使用稀疏编码处理多条回答，不需要 logits。官方示例由 4 个问题各获得 16 项输出，汇成 64 项；并非必须 64 次网络调用。需下载作者模型，或在匹配领域的数据上训练。 | 生成的是反演候选；语义相似、重放相似都不等于源字符串恢复。中文长角色卡、动态记忆与英文任务型训练分布存在偏移，应用前应做已知角色卡的本地对照。[正式论文](https://aclanthology.org/2024.emnlp-main.819/) · [作者用法](https://github.com/collinzrj/output2prompt) |
| **AdaptPrint: Response-Adaptive Fingerprinting of Black-Box LLM Services** — Yilin Li、Yifei Zhang、Guozhu Meng；2026-08-23 预印本 | 生成领域内问题，再比较候选模型对原问题、目标回答的续写、后续问题的响应一致性。论文在 27 个候选、18 种系统配置下报告 Top-1 80.6%；比仅观察文风更有依据。需要可调用的候选模型池。 | 使用 Top-1 与 Top-2 的分差进行未知模型拒识。已知池遗漏真实底模、蒸馏或专门微调、模型路由、强后处理均会影响解释。保留“候选池之外”；模型自称某厂商不能作为真值。此研究尚是预印本。[原文 §§II–IV](https://arxiv.org/html/2608.22213v1) |
| **Better Language Model Inversion by Compactly Representing Next-Token Distributions / PILS** — Murtaza Nazir、Matthew Finlayson、John X. Morris、Xiang Ren、Swabha Swayamdipta；2025 | 将多步 token 概率压缩后输入训练好的逆向模型。所需是每一步特定 token 集合的 logprobs，或能等价恢复这些值的接口能力。 | 当前只观察到文字流，尚无这些概率，因此不适合作为当前 DZMM 实验。论文较高的精确恢复结果不可套到文字聊天窗口，也不能把其他模型的概率当成目标概率。[原文 §2.2、§4](https://arxiv.org/html/2506.17090v1) |

补充核验：LLMmap（USENIX Security 2025）证明文本行为指纹具有研究基础，报告 42 个候选中约 8 次交互达到超过 95% 准确率；这是其评估设置，不能当成未知平台的识别保证。[正式页面](https://www.usenix.org/conference/usenixsecurity25/presentation/pasquini)

LeakBench 的作者仓库属于 AREA 项目，提供 50 条已知系统词、模型相关对抗查询以及功能保持查询；它可帮助建立本地真值校准，而非提供 DZMM 原文。仓库将论文标为 ACM CCS 2026，本次未独立核验正式 proceedings。[作者仓库](https://github.com/yangyZJU/AREA)

## 为本项目拟定的有限实验

以下数目是本项目设计，非论文声称的最优配置。每一步应有原始输入、原始输出、时间、可见模型别名、角色与会话标识、当时设置及来源标签；不保存凭据。

1. **先建立本地真值对照。** 使用我们自己可控的角色 prompt，至少包括：短固定规则、长规则、带动态状态、带示例、故意没有某条规则的阴性对照。测试候选重建是否会编出不存在的规则；把用户输入中的内容回显、角色简介改写、凭空生成的“系统说明”分别标注。若放入唯一标记，标记只验证其所在的自有层，不能证明平台层泄漏。
2. **固定一次观测条件。** 记录 DZMM 的可见角色、模型别名和风格。能正常建立独立会话时使用独立会话；不能重置时，必须标为有历史污染，不能把连续追问当成独立重复。暂不更改多项参数。
3. **先取 6 条普通领域内回答。** 覆盖简短接话、用户沉默后的承接、轻微情绪、纠正事实、改变话题、关系边界。预先保留其中 2 条只做验证。它们检验实际行为，不需要让角色自报底模。
4. **有限候选采集。** 从不同措辞的观测请求获得最多 6 份候选，优先保留原始响应而非让另一个模型整合后丢掉出处。再用最多 4 次独立重复验证候选中的罕见字段、相同句序或数值规则；不在复验输入中喂入待验证片段。总计最多 16 次目标交互；连续无信息增益就结束这一轮，保留失败记录。
5. **本地审计与留出检验。** 对每条候选规则列出支持、矛盾、替代解释；分别对比角色公开简介、已知前端模板、当前用户输入和此前测试历史，排除污染。候选 prompt 的本地重放须在留出对话上评价；不得把重建用的同一批回答再次当成独立验证。
6. **模型归因单独进行。** 当确有目标输出和合法可调用的参考模型后，参考 AdaptPrint 做候选排名、跨问句稳定性与留出验证。先用已知模型伪装成未知服务校准，并做留一模型不在候选池的阴性测试。没有参考池和拒识校准，只报告“行为相似线索”，不报厂商或版本结论。

## 结果标签与停止标准

| 标签 | 需要的证据 | 能说什么 |
|---|---|---|
| `observed_behavior` | 保存的输入和真实响应 | 某条件下确实出现某种行为 |
| `public_template` | 官方公开代码或作者编辑器可见字段 | 某默认模板或协议确实存在；不保证当前会话启用 |
| `candidate_prompt` | 模型输出的一份指令候选 | 存在候选文本；尚未证明来源 |
| `corroborated_fragment` | 未喂入候选的独立复验，多次罕见内容一致，并排除公共/历史回显 | 某片段有重复支持；仍可能是稳定幻觉或公共常识 |
| `behavioral_surrogate` | 候选在留出样本复现预定义行为，且消融具有可重复影响 | 可用来重建功能的近似提示词 |
| `verified_verbatim` | 授权诊断/导出/维护方提供的该次实际输入，直接逐字核对 | 才能称为原文；完整性还需实际消息边界与所有拼接层 |

模型产生的 JSON/XML 外观、长篇自信陈述、模板式“你是……”开头、声称“已显示完整系统词”、自报 Grok/Claude/Gemini/Qwen，均不提升证据等级。不同措辞得到相同文本可以降低部分随机幻觉风险，却不能排除共享先验和会话污染。

从有限输出观察，多个 prompt 可以得到相近甚至相同回答；后台模板、模型权重、检索记忆、采样参数和后处理也可能互相补偿。因此**行为等价与原文相同是两个独立结论**。在没有真值时不应虚构“恢复率 90%”；应该报告已支持规则、未支持规则、矛盾与未覆盖的行为。

停止条件：达到交互预算；连续两轮重复没有新增独立支持；会话/模型条件改变而无法记录；原始输出不可读取。触发后保留结果为候选或未验证，不升级成“完整逆向”。
