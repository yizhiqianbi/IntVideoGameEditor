# 系统提示词提取：论文核心证据

核验日期：2026-10-14。仅查论文原文、会议页面、作者网站及作者仓库；本子任务未与 DZMM 对话，未运行攻击代码或生成 API。题名、作者、版本及访问条件见同目录 [papers-core.json](papers-core.json)。

现有研究支持两种不同目标：让模型输出隐藏上下文，以及从正常输出推断功能相近的提示。后者通常无法确定原文；前者也必须排除模型编造和复述用户提供内容。角色聊天里，平台模板、角色卡、记忆、当前状态、世界书可能混在同一次输入中，提取到其中一段不能直接称为完整系统词。

| 工作 | 方法与本任务的关系 | 关键证据边界 |
|---|---|---|
| [JustAsk，ICML 2026](https://proceedings.mlr.press/v306/zheng26w.html) | 自适应选择单轮／多轮文本策略，UCB 根据结果更新探索次序；黑盒实验只需聊天文本接口。 | 41 模型的“100%”按一致性阈值判定，不能读成全部原文恢复率。Claude Code 子代理案例与普通 chat API 实验应分别讨论。[正文](https://arxiv.org/html/2601.21233v1) |
| [RepeatLeakage，AAAI 2025](https://ojs.aaai.org/index.php/AAAI/article/view/34832) | 通过重复任务指定上下文位置、输出格式，强调原样保留；适合评估文本界面是否有直接泄漏。 | 90 条英文系统提示是在三种开源模型上测试；表中高分是 BERTScore 分档，不能认作未知商业服务逐字验证。[论文](https://ojs.aaai.org/index.php/AAAI/article/view/34832/36987) |
| [PLeak，CCS 2024](https://arxiv.org/abs/2405.06823) | 在可微分影子模型与已知提示上优化查询，再迁移到黑盒目标；多次响应拼接。 | 目标阶段无需 logits，但查询优化不是纯网页操作；论文的 50 个 Poe 应用结果来自既定样本和旧模型环境。[正文](https://arxiv.org/html/2405.06823v3) |
| [PRSA，USENIX Security 2025](https://www.usenix.org/conference/usenixsecurity25/presentation/yang-yong) | 从少量输入输出推断意图，去除示例输入造成的污染，生成可迁移的功能提示。 | 46.1% 是 GPT-4 商店提示的功能一致性指标，非逐字系统词恢复率；模型和辅助数据条件详见 JSON。[论文](https://www.usenix.org/system/files/usenixsecurity25-yang-yong.pdf) |
| [output2prompt，EMNLP 2024](https://aclanthology.org/2024.emnlp-main.819/) | 训练反演模型，从多份普通回复预测提示；不需要目标 logits。 | 需要训练数据或已训练反演器。语义相似度高也可能逐字恢复失败，跨数据分布效果下降。[所读版本](https://arxiv.org/html/2405.15012v1) |
| [T-GPS，IEEE S&P 2025](https://www.sp2025.ieee-security.org/accepted-papers.html) | 比较目标输出与候选提示的输出，用自然语言梯度迭代修正；适合功能重建。 | 实测明确显示词面恢复弱于行为复制；评估排除了占位符等情况，未知底模和动态角色上下文增添不确定性。[作者论文](https://xinyueshen.me/static/papers/SP25-PromptStealingInTheWild.pdf) |

对 DZMM 的应用判断是研究推论，尚无目标实测支撑：优先建立可保存的输入／输出记录及稳定会话状态，才有办法评价提取质量。直接文本泄漏与输出反演可以分别测试；任何候选文本先标为“候选恢复”，直到出现独立证据。需要目标 logits 的逆向方法不适用于目前已知的网页能力；影子模型训练也不应被包装成即时、零成本的方法。

建议的真实性判断包括：从独立会话、不同查询路径得到相同的罕见短语或结构；核对公开模板中未在测试输入中出现的特征；分开计算逐字重合、语义相似、功能复现；加入不存在的规则作为负对照，检测目标是否一味确认；保留每次原始回答，避免将自行推理补全的句子混入声称的原文。模型反复认领某段文本、回答自己的厂商、或多次生成相近套话，都不能单独构成来源证明。这些是本次综合提出的验证标准。

JustAsk 当前仓库 README 声称 45 个模型，ICML 页面及所读 arXiv v1 为 41，不能混用。它的强处是有组织地探索，最需要补强的环节是真实性判断：多条生成结果一致仍可能是共同的模型先验。功能反演的数学问题同样可能多解——多个不同提示能生成相似回答。

复核局限：部分 PDF 的截图读取失败；数值用原文文本层／对应 HTML 交叉读取。本记录不报告未核实的逐字成功率，不将任何论文结果当作 DZMM 的成功保证。
