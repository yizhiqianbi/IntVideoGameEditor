# 叙梦 · 心动陪伴

一个本机运行的纯文字角色聊天原型。Yume / Nari 是原创成年角色；提示词、角色卡与系统实现均可审阅，不声称还原 NariYume 的私有模型或 prompt。

这版把亲近口吻、实际聊天内容、用户事实记忆和主动发言节奏分别处理。开放闲聊参考近期真实回复，减少重复题材、讨夸行为和相同的气泡节奏；具体问题优先直接回答。一次可以一条说完整，也可以自然发两三条。新增持久的角色生活事项：她实际说过的行动可以留下待做下一步，到时间后重新考虑是否有新进展值得分享；生活连续性不再只靠回复后的三次续聊。

## 运行

需要 Node.js 22 或以上。纯聊天服务无额外依赖；站内入口使用根项目已有的 Next.js 依赖。

在仓库根目录执行 `node scripts/xumeng-companion-dev.mjs`，同时启动/复用聊天服务和叙梦站，打开 [AI 女友](http://127.0.0.1:3010/xumeng/girlfriend)。酒馆页面和会话处理保持独立。只启动纯聊天服务：

```sh
cd experiments/character-chat
npm start
```

打开 <http://127.0.0.1:3227>，服务只监听本机。

主动核心的交互架构说明在 <http://127.0.0.1:3227/architecture.html>，区分当前实现与后台投递等后续层。

启动时依次读取根项目 `.env.local`、此目录 `.env.local`、进程环境变量。支持已有 `OPENROUTER_API_KEY` / `OPENROUTER_BASE_URL` / `OPENROUTER_MODEL`；也可复制 `.env.example` 并用 `CHARACTER_CHAT_API_KEY` / `CHARACTER_CHAT_BASE_URL` / `CHARACTER_CHAT_MODEL` 单独配置兼容 OpenAI Chat Completions 的服务。`CHARACTER_CHAT_PORT` 默认 3227。凭据只在服务端。

当前默认 `deepseek/deepseek-v4.1-flash`，环境变量仍可覆盖。默认启用 Planner → Replyer：`CHARACTER_CHAT_PLANNER_MODEL` 可单独指定决策模型，否则与回复模型相同；Planner 使用 `CHARACTER_CHAT_PLANNER_REASONING_EFFORT`（默认 none），回复器使用 `CHARACTER_CHAT_REASONING_EFFORT` / `OPENROUTER_REASONING_EFFORT`。Planner 温度 0.35、超时 25 秒；Replyer 温度 0.8、超时 90 秒。`CHARACTER_CHAT_PLANNER_ENABLED=false` 仅作为旧单阶段兼容开关。凭据始终留在服务端，未配置模型时为明确标注的演示模式。

## MaiBot 架构移植

参考 [MaiBot ac6ed61](https://github.com/Mai-with-u/MaiBot/tree/ac6ed61b7b9c971ad94921de3b16fa6f63c36a20/src/maisaka) 的决策/表达分离、wait 和会话事件机制，为现有 Node.js 服务独立实现；没有复制其 GPL 源码或原始 prompt，也没有把整套 Python 进程、QQ 适配器或 A_Memorix 接进来。

- `planner.mjs`：短历史、当前意图、关系、隐式状态、可召回记忆 → reply / wait / silent；结构化输出严格校验并绑定会话版本与本轮输入。
- `replyer-context.mjs`：只提供人物声音、当前事实、已选择记忆与回复方向，去掉旧策略堆叠和 few-shot；保留纯对白 JSON 契约。
- `provider.mjs`：分别路由 Planner 与 Replyer。Planner 失败时前台降级现有回复链、主动回合保持安静，并记录降级；格式无效最多修复一次。
- `companion-runtime.mjs`：持久保存限量的行动诊断（不含思维链）；wait 重新排一个有限期机会，消耗预算，防止无限模型轮询。
- `/interrupt`：取消旧请求并等待完成边界，返回已提交 receipt。前端据此决定是否把旧输入合并重发，避免读旧版本时丢消息或重复提交。

具体边界、站内代理和验证见 [女友模块说明](../../docs/xumeng-companion.md)。

## 可以试的几轮

- 「来啦」「嘿嘿」「你怎么这么乖」：看她怎样接短话，而非每次等一个完整问题。
- 「撒个娇，别安排小游戏」「你自己也说点」：看她自己的小反应和实际内容。
- 「抱一下，就一句」：临时短回复；下一轮恢复原来的篇幅偏好。
- 「我叫林舟，叫我阿舟，我喜欢喝乌龙茶」：查看记忆中的原话与来源；可以修正或删除。
- 「那个话题算了，别继续」：结束当前内容，不持续拉回旧物件。
- 「这次别撒娇，把‘我晚点到’改得礼貌点」：配合办事，临时语气要求不会永久改变角色。
- 「以后回复短一点，别追问」「别叫我宝贝，叫我阿舟」：保存表达偏好；身份记忆与风格设置独立。
- 「说英文」或从面板选语言：当前指令优先。
- 新建后先不输入，或聊完暂不接话：页面可见且输入框为空，她会按当前意图重新考虑要不要自己说话；可以安静，不催回应。
- 「我去忙了」「晚安，我先睡了」：主动暂停，下一条真实用户消息才能解除。
- 「你挑件自己想做的小事去做，待会有变化再告诉我」：右侧能看到有对白来源的角色日常；没新进展时可以不发消息。

## 对话与主动机制

本人聊天规范共用于普通回复和主动发言：显示内容只有她实际说的话，自身动作和感受可以直接说，不加角色名标签、动作括号或小说旁白。后台当前关系明确传给模型；温柔与亲近邀请可以自然回应，身份、分享深度和承诺仍按阶段与真实互动表达。两个角色的声音示例也遵守这条规范。明确的标签或动作包装会在流式预览之前及最终解析中被拒绝，保留原文和用户草稿供重试；不会静默改写或者自动额外调用模型。正当括注、乘号、强调和引用保留。格式检查不能代替模型对所有叙述语义的理解。

`characters.mjs` 保存背景、性格、独立声音示例与作者提示。`engine.mjs` 按当前内容选少量示例，组装人物、运行状态、实际历史、当前输入和末尾写作要求。闲聊空白、自主选择和“然后呢”各有内容方向：具体发现、选择的原因、已有想法的新结果；安静、告别、一句回应与实用任务优先。独立示例不属于真实聊天，不能提供用户事实或共同往事。

`conversation-direction.mjs` 从最近六个实际助手轮次导出软方向，给已经反复出现的题材、言语行为和示例降权。它在开放闲聊、低信息续聊、换题、亲近和主动机会中起作用；具体问题不注入随机方向。每位角色有十组不同兴趣/接话角度，声音参照不再固定选第一条。方向只参与写作，不改变用户事实、关系、历史或情绪，不用随机换题或情绪配额制造“多样性”。词法分类只是提示，不能替代模型理解或人工判断。

`characterBeat` 是角色自己的虚构小事、感受和下一步，只作背景连续性，不要求每条对白汇报。应用管理它的年龄与退场，用户结束话题也会关闭对应角色内容。用户事实只来自可验证的原话或手动记忆。

`memory-layer.mjs` 引入了 EbbingFlow 的轻量记忆底座：原始用户消息作为证据，记忆沉淀为带 `sourceMessageId`、`confidence`、`impact` 和 `evidence` 的 Event；每五个用户轮次形成一个 Episode，计划类事实同时形成可追踪的 `openLoop`。Prompt 组装时按 fact / summary / long_term / semantic 意图做词法召回，并用按记忆类型配置的 Ebbinghaus 时间衰减排序。它暂时不依赖 Neo4j 或 Chroma，也不把记忆沉淀放进响应关键路径；这层解决的是连续性和可追溯性，不替代情绪、关系弧或主动调度。

`dialogue-state.mjs` 维护一份不展示给用户的隐式对话状态：当前主要说话行为、未解决的用户点、角色上一条问题、边界阶段、修复标记和最近回复账本。它把“用户还在坚持同一个越界请求”和“用户已经转向亲吻/拥抱”分开处理；同一拒绝句或高度相似的回答不会直接落库，服务端会带着换角度约束重试一次，仍重复时 AI 模式返回可重试错误，不将固定台词伪装成模型回答。提示词只拿压缩后的控制摘要，不把内部状态当成角色对白。

普通用户轮通常为两次模型调用（Planner + Replyer），命中重复闸门时复用本轮决策追加一次换角度生成。支持完整短消息级流式显示：一条 JSON 字符串生成完整便先显示，全部响应验证后才提交存档。失败会撤回临时预览并保留待发送内容。Enter 后有 700ms 合并窗口；生成期间继续发送会中断未提交的旧生成，读回 receipt 后将未提交输入与新分段一起重新生成。已提交消息不会再次拼入；不同气泡不重复调用模型。

主动计划是可取消的 `reconsider` 意图，不是预先写好必须送出的台词。开场也可以触发；普通陈述的首个机会至少等待 12 秒，后续至少 35 秒；如果角色刚问了一个问题，会先给用户至少 45 秒，再最多轻轻提醒一次，提醒发出后等用户回答，不连续催促。单个计划有效期最多 5 分钟，每段在没有新用户输入时最多 3 次生成机会。空回复也消费一次预算。恢复当前页面时过期意图会被替换，到点读取最新会话再生成。输入、输入法组合、隐藏页面或切会话会取消；旧版本结果不能提交。右侧开关可以关闭主动聊天。

`proactive-runtime.mjs` 维护独立的 `agency`：生活事项的状态、下一步、版本、真实助手消息来源、下次评估时间，以及已消费机会记录。模型可在一次正常回复或主动回复中提出 `life`，状态必须逐字出现在这次真正发出的自身行动对白中，支持中文省略主语，不能来自引语、第三人或用户动作。时间推进只产生待考虑机会，不把待做的事预先记成完成。只有实质的新状态和下一步才能建立新版本；同一版本最多考虑一次，空回复也记账。

具体生活机会拥有独立窗口：至少间隔 120 秒，滚动 15 分钟最多 3 次。旧续聊预算耗尽后，仍能在前台因为未消费的具体事项开口；没有事项就不会启动这一层。前台定时器只调用轻量的 `/presence` 检查，模型只在具体机会被选中时调用。告别/忙碌暂停联系并保留未完成事项，明确关闭话题则关闭对应事项，已完成或已关闭事项只接受用户明确重启。词法检查用于约束重复与归属，仍不能替代模型语义判断。

主动消息不添加用户消息、不写用户事实、不提高关系。没有 Codex 定时任务、后台长期循环或关闭页面后的推送。

## 数据与边界

存档在 `.data/sessions`，本地角色会话各自独立；最多保留 400 条消息。近期上下文按最近 12 个用户交换取回、总量限 12000 字；更早内容用有说话者、日期与来源的有限原文片段补充。记忆证据、Episode 和 open loop 也随会话保存，但当前仍是本地词法召回，没有跨会话共享档案、Neo4j 或向量数据库。复杂事实可能漏记，可手动更正；模型台词仍可能有误读或重复。

存档原子替换，消息唯一编号防止重试重复生成；版本冲突、断连或上游失败有明确处理。`.data` 和 `.env.local` 从 Git 排除。右侧可以修改记忆、调整语言、关闭主动并导出对话。
