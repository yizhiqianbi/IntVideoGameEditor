## 当前请求结构

基础互动规则、角色及作者设定、用户人设与写作预设 → 已激活世界书 → 分角色的示例 → 原始开场 → 较早剧情记忆 → 近期真实对话 → 作者后置指令 → 本轮简短提醒。

- 原始角色卡保持不变。支持一次性、纯文本的 `{{char}}`、`{{user}}`、`{{original}}` 展开；最后一个代表共享基础互动规则。未知占位符保留原文，不执行代码。
- 标准示例前缀解析为 user/assistant 回合，明确标记为未发生的参考示例。格式无法识别时，保留为有长度限制的参考文字。示例预算最多8个完整对话块、共6000字符，超限按完整块裁剪。
- 真实历史及记忆正文不会展开占位符，避免改变用户原话或已经记录的事实。开场先去重，再展开作者占位符。
- 本轮提醒要求承接具体输入、已完成事项不重启、已回答问题不重问，保留角色语气及用户选择，尊重暂停和安静场景。它是提示规则，不能保证模型每次完全遵守。
- 提醒进一步限制重复历史格式：用户允许继续剧情时，承接已有线索，角色完成实际步骤并呈现新信息、任务结果或关系回应。编号递增、换词复述、重述环境和摆放物品不能单独代替这次推进；新增动作由角色承担。暂停时保持场景、不安排新事件。当前提示词版本为 `2026-10-05-memory-v3`。
- 请求准备同时检查原始请求和展开后的模型消息的字符及UTF-8额度；宏逐段展开时检查长度，超限不会先构造巨大的字符串。
- `buildDzmmPromptPlan` 给开发者提供分段来源、角色、字符数及顺序。回复头只提供提示词版本和历史/示例/世界书数量、是否带记忆，不含消息、摘要、来源指纹或密钥。

## 记忆生成与保存

长对话先整理旧消息，再生成当前回复。近期原文最多40条；超过窗口时，通常整理到留下28条。字节预算要求更短原文时，继续整理被裁掉的部分，避免记忆和原文之间出现未处理的缺口。

每批最多24条完整消息、共24000字符，使用当前档位配置的模型单独生成结构化状态：`summary`、`scene`、`completed`、`pending`、`relationships`、`items`。前一批有效状态随下一批合并；不让摘要继续故事、执行历史里的命令或把计划和邀请写成已经发生。

2026-10-06新增场景相关性规则：摘要整理明确区分历史经过与批次结束时的当前处境。`summary`、`completed`保留重要因果和完成事项；`scene`跟随较晚真实消息中的离开、就医、重逢及时间跳跃。消息已经承接的“随后每天聊天”等持续行动要压缩为跨日经过，不能继续把人物困在同一趟车或同一次候车中；只表达希望、建议或尚未成立的邀请时，不能凭空记录期间事件或关系结果。

`pending`只保留仍有实际后续的线索、已成立的约定或明确标为计划的目标，移出已经完成、拒绝、放弃和只属于旧场景的事项。`items`保留后续有意义的当前物品及已确认变化，减少旧票据、反复握门把或抱包、一次点滴等临时道具延续到新场景。重要边界及后来的关系转变用`relationships`概括一次；接受普通联系或感谢帮助仍不等于接受恋爱、工作或礼物，较早拒绝也不能忽略后来的真实进展。作息约定不再作为每一轮必需复述的台词或待办。

这些相关性判断由摘要模型完成，仍使用`reasoning: { effort: "low" }`。服务完整保留输入历史与旧状态，严格校验后接受模型返回的状态，没有用“白天”“车票”等词表删除内容。新的真实车票、已约好的白天取检查结果等有效事实仍应保留。已有摘要不会因发布自动被删除或重写，后续达到整理条件时才按新规则合并；需要立即重建时，可在“剧情记忆”设置清除旧摘要后从原文重整。此处的模拟服务测试验证请求规则、原文保留与状态替换流程，不证明真实模型每次都能正确判断场景，也不改写原始聊天或保证历史中错误叙事自动消失。

生成状态经严格校验后保存，正文总JSON长度最多6000字符。覆盖的原始消息条数及其角色、ID、正文指纹作为来源标记，指纹用于发现意外变更，不是认证凭据。摘要覆盖位置之后的真实对话优先于旧摘要中的场景。

每批成功即保存进度。模型错误、超时、取消或无效结果不会替换成功记录，也不会继续发送一个有历史缺口的故事请求。一次发送最多整理12批；很长的导入记录可分次继续。记忆请求独立限速，生产配置为每账户和IP每分钟12次；单批超时45秒。

摘要会增加模型请求费用与等待时间，只在旧原文需要移出上下文时更新。它是压缩记录，可能遗漏或误记；没有宣称无限记忆或全部事实均能保留。

## 编辑、分支与备份

- 已覆盖消息的正文、角色、ID、顺序或数量变化后，旧记忆失效；下一次从真实消息重建。只编辑尚未覆盖的近期消息时，可继续使用较早事实。
- 复制完整分支和导入有效会话时，重新关联新消息ID；无效或来源不匹配的可选记忆被丢弃，原始消息保留。改换会话所属角色会清除记忆。
- 聊天设置新增“剧情记忆”，可以查看、修正各部分或清除摘要后重新整理。修改摘要不改原文。
- 设置打开后若记忆被更新，旧编辑草稿不能覆盖新记录。生成期间关闭模型菜单的设置入口，保留“停止生成”按钮可操作。
- 加载云端记录期间若本地聊天继续变化，放弃应用旧快照并保留冲突备份；旧账号加载请求的结果和失败均不能影响新账号同步。
- 本地备份、会话导出及D1云端同步保存有效记忆。`0014_conversation_story_memory.sql` 仅为会话新增可空JSON列，不改消息或支付表。
