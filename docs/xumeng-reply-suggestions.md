# 每条角色回复的「帮我想想」

2026-10-08 用户请求增加每次对话的行动建议。每条非空角色回复提供「帮我想想」。新建开场和每次完整成功的角色回复自动生成并展开三项：交流了解、行动探索、调整节奏。历史旧回复不在载入时批量补跑，可手动生成。结果由服务端校验三个固定方向、完整短文本与回复去重；场景适配和目标差异由专用提示词约束，格式校验不代表已完成广泛的模型语义质量评测。

## 交互与数据

最新回复的选项先填入输入框，需要用户确认发送。已有文字原样保留；切换选项只替换未被手动修改的插入内容，支持撤销。合并超过 12000 字时保留输入并提示整理，不截断。插入失败不提供额外付费生成的重试按钮，正常选择成功清除插入错误。

历史回复生成建议时，仅截取至该回复的真实前缀。选择后创建独立私人会话，保留选中回复，以新会话和消息 ID 重新绑定有效开场、剧情记忆及世界快照。原会话和原输入不变；分支只预填草稿，不自动调用聊天。

建议请求不会写入聊天、不触发记忆摘要、不应用世界补丁或推进真实/故事时钟。采用前缀匹配的已记录世界快照。独立后台控制器不占正文 busy、停止按钮、导航和同步队列，生成期间可以输入并发送下一句。前缀编辑、卸载和账号切换取消旧请求，回包再次核验原账号。失败只显示该条回复的提示，不删除正文、不弹全局登录、不自动重试。结果归属原回复。

建议保存在账号隔离的 sessionStorage 中，最多80条；保留结果和已尝试状态。收起、切页和刷新复用结果，不新增模型请求；中断记录提供手动重试。缓存不进入聊天或摘要，不跨设备同步。自动请求发起即消费该回复的资格，缓存淘汰也不会触发自动再次付费。

键包含真实消息前缀、角色与开场、有效用户设置以及该前缀的世界快照和记忆。后续世界更新不会使所有旧回复缓存失效；编辑前缀使对应结果失效。组合设定分块计算完整指纹，不通过截断掩盖尾部变化。

## 模型与费用

`POST /api/reply-suggestions`（兼容 `/api/dzmm/reply-suggestions`）复用现有服务器会话、Origin、请求 UUID 和账本能力。建议与正文使用独立限流键，各沿用6次/分钟。使用现有 fast 档模型、low reasoning，服务端输出上限512 Token；余额报价可降低上限，并重新生成请求指纹后预留。

按用户最新决定，不拆小模型，仍由现有模型的一次后台请求生成建议，独立于正文请求计费。只读材料压缩为有限人物说明、最近最多6条真实消息（合计3500字）、有效摘要与当前世界，全部供应商提示不超过6000字。不加入作者备注、样例、角色系统指令或开场模板，不把辅助 user 占位当成历史。JSON schema 约束三个分支，再由服务器校验方向与去重。一次非流式请求保留大小和45秒超时限制。

费用沿用当前 chat operation 的可信供应商实际成本 ×3 政策，未修改价格或计费开关。必须返回完整、不同的三项且 finish_reason=stop 才算有效输出；不足三项、重复、截断、异常、取消或超时释放无效输出预留。展开缓存和选择建议不新增模型费用；确认发送后另按普通聊天结算。供应商计量缺失仍沿用原有待结算/退款规则。
