# 叙梦本地经营日报

日报入口：`node scripts/xumeng-daily-report.mjs`。在项目根目录执行，默认统计北京时间前一个完整自然日。日报保存在 `output/xumeng/daily-reports/`，每个日期有可阅读的 Markdown 与机器可读 JSON；`latest.md` 为最新日期（可能包含缺失项），`latest-successful.md` 为最近一次取得正式经营数据的日报，`index.md` 为归档目录。后者可能不是最新日期，不可冒充当日数据。

日报包含账号增长、VIP 购买与手动续期、有效会员和到期提醒、签到发放、充值付款、Credit 入账与扣除、模型请求和已记录接口费用、图片视频语音任务、论坛与玩家任务、创作投稿、Telegram 反馈状态，以及公开主站 HTTP 与本地迭代台账。只保存汇总数字和模型等统计维度，不保存邮箱、用户名、私人会话、作品正文、反馈原文或密钥。

## 生成与补报

```sh
cd /Users/pencil/Documents/IntVideoGameEditor
node scripts/xumeng-daily-report.mjs
node scripts/xumeng-daily-report.mjs --date 2026-10-10
node scripts/xumeng-daily-report.mjs --date 2026-10-10 --refresh
```

默认不会重复采集同日已经完整生成的报告；缺失报告可重试。JSON 为真源，重复运行会修复缺失或中断写入的 Markdown 和最新入口，无需重查生产。`--refresh` 显式刷新；如果正式数据读取失败，不覆盖该日已经取得的正式数据，而另存失败记录。补报较早日期不会把 `latest` 或 `latest-successful` 倒退；损坏的原 JSON 会保留并报错。补报的“当前”指标始终指补报执行时刻，不能作为历史日末数据。

退出码 `0` 表示完整生成或已有完整报告；`2` 表示已生成含缺失项的报告或保留了先前有效报告；`1` 表示本地参数、文件或并发锁错误。采集失败列为“未获取”，不填 0、不引用陈旧报告冒充当日数据。并发锁为 `.report.lock`；异常退出残留时，先核对文件里的机器和进程是否仍在运行，再清除本系统的锁。

## 正式数据与权限

数据通过本机已安装的 Wrangler 和 `cloudflare/dzmm/wrangler.production.jsonc` 中的 `DB` 获取。程序只生成固定只读聚合 SQL：一次 SELECT / CTE 汇总，禁止传入任意 SQL；必须核对 D1 回包成功、单行结果、`rows_written=0`。不用网站登录 Cookie，也不向前端加入凭证，不改数据库、不创建订单、不支付、不签到、不发送消息或调用模型。查询文本可见统计边界，没有用户明细或密钥。

需要本机 Cloudflare 访问权限与网络正常。授权无法刷新时先恢复网络或代理；仍未恢复再在 `cloudflare/dzmm` 执行本机 `npx wrangler login`，无需把密码或 Token 发给 agent。正式配置文件只提供目标数据库，不保存授权密钥。子进程关闭 Wrangler 文件日志与使用量上报；采集错误只保留固定脱敏说明，不保存原始命令回包。

每日生成由 Codex 本地自动化运行，默认北京时间每天 09:00 汇总昨日。机器、Codex 和网络需要可用；调度成功不意味着当日数据已成功读取。未运行的日期可用 `--date` 补报。自动化仅运行采集程序，不自行修改产品、经营价格、会员权益、余额或迭代台账。

## 口径与已知限制

- 普通经营指标使用当前非演示、非游客、非 Super 账号。演示作者、游客和 Super 数量分列；Super 模型用量单列。未经标记的普通测试账号无法自动辨识；历史账号升权、访客转注册或删除及级联删除会影响追溯。
- 新增注册按注册批次的 `new_signup` 赠额凭据时间统计，包含游客转注册；当前账号创建时间另列。赠额功能上线前未保存这种凭据的历史注册不能追溯，不能把赠额来源和创建时间计数直接相加。
- 所有时间字段按毫秒处理，日报区间为北京时间 `[00:00, 次日00:00)`。当前会员、余额、待处理任务是采集时快照，不能与报告日期间混为一谈。
- Stripe 测试付款不计经营收入；实付按 `paid_at`，新建待付款不计收入；不同币种分别统计。充值与 VIP 使用各自订单，支付绑定与回调不重复计收入。
- VIP 需手动购买续期，不自动扣款。权益期排队不等于同时多个活跃会员。有效会员按账号去重，到期提醒考虑后续排队权益，不报告不存在的自动续费 MRR。
- 充值退款需已确认事实；订阅缺少独立退款金额与确认时间，无法构造当日完整退款现金流。营业实付与当日已知充值退款分别列示，不声称净收入或对账完成。
- Credit 入账按各账本来源，消费按实际终态账本；预留额度与释放预留不当作消费或赠送。社区任务积分与模型 Credit 分开。
- 模型费用只统计已保存费用；未知费用明确计数。API 成本缺少服务器、发信、手续费等，媒体冻结 SKU 也不等于供应商实际账单；不推算净利润。
- 模型与媒体以报告日发起请求为样本，展示采集时的状态、费用回填和未知数量，不代表供应商当日已出账成本。后续补核时，显式刷新同日报告可能得到不同结果。
- 登录会话和模型请求可提供活动信号，不能代表全站 DAU。无浏览量埋点；直播缺少统一 D1 会话/秒数/费用账本，这些指标暂记未获取。
- 创作内容只统计现存对象数量与有时间字段的新增/更新记录，不检查私人内容。主站 HTTP 200 只证明公开入口可达，不等于真实付款、模型或音视频验收通过。
