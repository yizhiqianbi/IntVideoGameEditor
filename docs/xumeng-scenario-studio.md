# 团本创作与房间

实现日期：2026-10-10。创作入口为 `#studio/scenarios`，新建为 `#studio/scenarios/new`，私人剧本为 `#studio/scenarios/:id`；邀请入口为 `#studio/room/:code`。

## 创作与参与

剧本包含公开简介、世界设定、任务目标、开场、2–8 个玩家角色位、最多 20 个阶段、AI 主持提示词和隐藏笔记。私人草稿允许不完整保存，开房前检查标题、目标、开场、至少两个已命名角色和一个已命名阶段。角色公开描述用于邀请选角；角色性格与秘密、AI 主持提示词及主持笔记只返回给主持。

房间从已保存版本冻结快照。后续修改或删除私人剧本不修改已有房间。主持创建房间、复制邀请、开始团本，开场作为第一条主持叙事发布。玩家加入一个空闲角色位，发布发言或意向行动；结果由主持确认。主持可以真人发布叙事，填写转场依据后原子推进一幕，也可按按钮生成 AI 草稿，人工检查后发布。生成使用默认 Grok 并按实际模型用量扣 Credit，保存、开房、真人发言不调用模型。AI gateway 由主任务提供 `/api/dzmm/scenario`；本模块不持有供应商密钥。

默认原创模板“雾港灯塔的失落航图”以核实线索、共同决策和可结束的调查为目标。阶段、地点和已发布事件是实际保存的状态；模板文字没有被宣传为自动心理指标或已验证的模型表现。隐藏资料不出现在邀请预览或玩家 GET 返回中。

## 一致性与恢复

私人剧本按用户及作品编号隔离，写入要求当前版本。发生保存冲突时保留本地草稿；只有整个服务端快照与提交内容完全相同才接纳丢失响应后的重试。浏览器恢复副本按账号、当前文档实例和作品编号分槽；删除时核对原始内容，只能删除本实例的同一修订，不能覆盖其他标签页或其他账号的稿件。JSON 备份严格检查字段并导入为新编号。

成员占位、房间版本和阶段更新在 D1 事务中执行。同一角色位的竞争加入只有一个成功。消息带客户端编号，同账号同编号同内容重试不会新增事件；改变重试内容会冲突。玩家不能发布主持叙事或改变阶段。离开后撤销房间读权限并释放角色位。结束后参与者可以读记录，不能继续发言。主持结束操作保留当前未发布 AI 草稿，仍可导出。AI 重生成先确认替换；草稿记录起始版本和阶段，房间发生变化时展示警告，发布前再确认。

房间每五秒低频轮询，隐藏页暂停。最近 100 条事件返回一次，可加载更早记录。每房最多 2,000 次普通发言；每账号最多 200 部私人剧本、20 个未结束的主持房间，房间列表返回最近 100 个。没有公开发布或搜索团本市场功能；邀请码是访问邀请，持码仍需登录并加入，才能读取房间内部内容。

## 文件与验收

- `src/lib/xumeng-scenarios.ts`：格式、原创模板、开房检查与导入导出。
- `src/lib/xumeng-scenarios-client.ts`：账户确认、请求、恢复副本和 AI 草稿流读取。
- `src/components/dzmm/scenario-studio.tsx`：剧本工作区、邀请选角、多人房间与主持控制。
- `cloudflare/dzmm/src/scenarios.ts`：`/v1/scenarios` 接口，以及供 AI gateway 使用的 `readScenarioRoom` 账户限定读取。
- `cloudflare/dzmm/migrations/0035_creator_scenarios.sql`：新增表与索引，不修改原有会话或钱包表。

开发验证为定向前端、后端 TypeScript 检查和一次性 Miniflare D1 认证 API 测试。API 测试实际注册普通用户，覆盖私人隔离、并发占位、消息幂等、快照冻结、主持资料隐藏、阶段 CAS、重开、离开、结束和外源拒绝；不使用原有私人账号、真实模型、真实付款或公开投稿。客户端测试另覆盖失败保稿、错账号拒绝、丢失保存响应与多标签恢复。页面实测、生产资源、真实模型用量由主任务的轮次证据记录，本文件不把这些未执行的验证视为完成。

## 视觉与交互依据

视觉：沿用叙梦深色底面、粉色主操作和克制分隔，让正文与角色位成为工作区主内容。内容安排：列表选择作品或加入邀请，编辑正文加右侧主持资料，房间时间线加成员与主持控制。交互：按钮快速反馈；同步失败保留已发布记录并可重试；窄屏把成员和主持控制移到时间线前，表单纵向排列。没有装饰性首页海报，也不把不适用于操作页面的营销文案塞进创作流程。
