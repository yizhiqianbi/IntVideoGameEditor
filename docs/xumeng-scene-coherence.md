# 叙梦场景连贯性修正

2026-10-06，提示词版本 `2026-10-06-scene-v4`。

用户反馈：连续多日聊天仍停在同一趟火车里；转场和多年后相遇依旧反复写硬座票、抱包、白天联系；要求安慰时没有展示实际说了什么。角色可以保留自身态度，但这些时间、场景和回应上的重复不应成为固定模板。

## 已定位的原因

- 原隐藏时钟将模型明确跳时上限设为10,080分钟，即七天。“三年后”可能改变可见文字而没有改变累计分钟，或仅改了显示日期。
- 开场、旧摘要和近期历史共同传入模型，隐藏世界状态原来放在提示的最后；旧场景的道具与一次性对白容易覆盖当前互动。
- 原摘要指令强调保留物品、承诺，却没有明确区分历史事件、当前场景和仍有效的线索。
- 用户自主权指令没有清楚区分未经授权的代写与用户明确请求的日常过程概述、安慰对白。

## 本次处理

明确的叙事跳时由本地解析后预先推进剧情时钟，提示与最后接受的状态使用同一锚点。模型再提交时长或剧情日时不会重复累加。支持分钟、小时、天、周、月和年；未知日历下按月30天、年365天折算，单次上限100剧情年。这不等于实际日历日期计算。

解析采用保守规则，引用、问题、回忆和未来计划不自动推进；没有给出确切跨度的“每天聊天”等动作不会在本地被猜成某个天数。模型可以在用户授权范围内概述几天的过程，以证据支持的短期蒙太奇记账。大幅跨度后的旧钟点和日期标签不会直接充当新锚点；短暂等待仍保留适用的日期。

最后一段本轮提醒先校准当前时间、地点和交流方式，再提示过程概述、必要回应与关系的细微变化。世界状态位于该提醒之前。剧情开场和原文历史全部保留，只改变它们如何被解释，不修改用户原来的聊天。

本地统计最近四条角色回复里至少三次出现的短片段，最多提示六条重复措辞。它们只作为写作统计；当前用户正在谈及的相同片段不会被单独列作重复项。没有关键词禁用表，也不因词语重复删除事实或改变人物态度。

摘要在下一次实际整理时区分历史、当前scene、仍有效pending、长期items及关系节点；已结束旅程的票据和旧动作不默认进入新场景。重要边界保留为关系背景，正常的新互动不需要反复朗读完整警告。接受陪伴、帮助或经过时间不自动等于恋爱或同意。

思考参数保持 `low`。本轮校准及明确跳时解析不增加模型调用；历史摘要沿用原来的触发机制。

本地回归覆盖明确多年跳转、逗号后疑问/计划/回忆、两种时间模式、重复时长保护、跨日及短时日期、当前用户相关道具、原文完整保留、提示顺序、摘要上下文与low设置。Cloudflare真实保存测试使用原创成年人物及新建临时游客，最多两次回复，结束后清理该测试账户。
