入口：https://xumengchat.top/#admin 。在“我的”页面也有 Super 管理入口。使用正式 Super 账号登录，游客和普通账号在后端被拒绝。

## 站主账号

正式账号是 `super@xumengchat.top`，昵称“叙梦管理员”。密码只保存在站主本机 `/Users/pencil/.codex/private/xumeng-super-credentials.json`（权限 0600），不写入代码、发布文件或聊天。账号已创建，正式接口与页面均已验证。

## 本地开发默认登录

叙梦专用 Next 本地入口默认使用本机 Super 凭据建立真实后端会话；普通 `npm run dev`、线上网站和 production 构建均不启用。使用以下命令启动后打开 `http://127.0.0.1:3010/xumeng`：

```sh
node scripts/xumeng-dev.mjs
```

专用脚本固定绑定 `127.0.0.1:3010`，只在子进程服务端环境设置 `DZMM_LOCAL_SUPER_AUTO_LOGIN=1`，并默认连接 `https://dzmm-backend.850587960.workers.dev`。需要隔离本机后端时可将 `DZMM_BACKEND_URL` 设为 loopback origin；脚本拒绝其他目标。`node scripts/xumeng-dev.mjs --dry-run` 仅检查启动配置，不启动服务、不读取账号凭据。

首次匿名请求 `/api/backend/v1/session` 时，Next 服务端读取当前系统用户拥有的 0600 普通凭据文件，拒绝符号链接，并通过 `/v1/auth/login` 验证文件中的指定账号 ID、邮箱与 Super 身份。密码只进入服务端到后端的登录请求，浏览器只收到经过核验的账户信息与 HttpOnly 会话 Cookie；凭据和启用标记均不注入前端包。传送密码的后端地址仅允许 loopback 开发后端或上述精确 HTTPS Worker origin，任何跳转均不跟随。

已有账号会话（包括游客）原样保留，不被默认登录覆盖。成功退出时写入本地 HttpOnly 退出标记，后续刷新继续使用游客流程，不会反复强制登录；若要重新启用默认登录，先在浏览器开发者工具中清除该本地域名的 `dzmm_local_super_optout` 和 `dzmm_session` Cookie，再刷新页面。无需清除其他浏览器草稿或备份。缺少凭据、权限不符、登录失败时保留原匿名流程；自动登录失败至少间隔一分钟才重试。

请求还需通过显式启用标记、development、loopback URL／Host／Next 转发地址与同源检查。NextRequest 没有可验证的 socket 身份，转发头可能被客户端伪造，所以专用脚本的 loopback 绑定是必须的部署边界；不要在普通开发服务上手动启用该标记后绑定 `0.0.0.0`，也不要通过隧道开放或置于公网反向代理之后。此功能不增加余额、不修改权限，也不自动签到、充值或创建测试剧情；后续操作仍访问真实账户与钱包。

纯 Vite 页面（例如 `cloudflare/dzmm-web` 的 5174 端口）不提供 Next 服务端 API，不能读取本机私密文件或执行该默认登录。需要本地默认 Super 时使用上面的 Next 开发入口，不把密码加入 Vite 配置或浏览器代码。

## 钱包与权限

站主采用普通数值钱包：一次性授予 `1,000,000,000 Credit`，使用时与普通账户一样预留、按实际用量结算并退还未使用的预留；Super 身份只管理权限，不再免扣费或显示 ∞。授予来自独立管理账本，不记为充值订单或支付收入，重复初始化不会叠加。普通账号费率不变，给其他账号授予 Super 权限不会自动赠送这笔初始余额。

聊天、剧情记忆及小说生成保存实际 Token／模型成本。此前已经建立的免扣费用量保留原始记录和结算方式，不追溯扣款；之后的新请求统一进入普通消费账本。VIP 功能直接开放，不要求购买会员或签到；语音与图片没有每日次数额度，单次文件、长度、频率、服务配置和供应商成本上限仍有效。实时影像的 Super 内测权限沿用现有服务授权，服务器未连接时无法开播。

## 后台功能

- 概览：正式／游客／Super 数量、有效 VIP、钱包汇总、待审核、用量核对、各渠道币种和环境的已支付原始金额。
- 用户与权限：按邮箱、昵称或账号 ID 查找、分页、查看钱包和 VIP 状态；授予或撤销 Super。
- Credit 调整：每次正负整数且非零，上限 1,000,000；扣减不能占用已预留金额或制造负可用余额，管理员调整与支付事实分别入账。
- VIP、支付订单、模型用量：只读列表与账号筛选，不触发付款、退款或签到。
- 操作记录：管理员、目标账号、调整前后角色／点数、原因、时间与请求编号。
- 角色审核与论坛管理：接入已有审核、举报及论坛管理模块。

不能撤销当前使用账号自己的 Super，服务端保证至少保留一个 Super。公共注册接口不能授予该角色，浏览器自报权限不能获得后台权限或余额。密码、会话 Cookie、模型凭据及原有私人会话正文不通过管理接口返回。

## 可靠性

角色和余额操作要求非空单行原因，并显示确认页。服务器在同一 D1 原子批次内重新核验管理员角色和会话，写操作记录并应用变化。幂等键绑定管理员与请求编号；相同操作重试返回已有结果，编号被用于不同操作时返回冲突。已尝试操作的重试冻结原请求，避免响应丢失后重复入账。

查看列表采用身份校验与分页，客户端在账号切换时隐藏旧数据并使旧请求失效；正式页面以账号及角色为组件身份。管理接口为 `/api/backend/v1/admin/*`，返回 `private, no-store`。

`0022_admin_super.sql` 增加管理审计／调整与历史 Super 用量表。`0023_trusted_credit_grants.sql` 增加可信管理授予账本并加入余额视图，单笔正整数上限 10¹²；没有公开写入接口。站主初始化脚本绑定指定 Cloudflare 账户、D1、邮箱及已有账号 ID，用固定授予编号去重；不改写支付、退款、会员或普通消费历史。

## 直播产品方向

用户导航的“AI 直播”入口为 `#live`，返回角色页，创作中心不再放直播入口。默认方向暂按一对一 AI 主播互动，待站主选择后确定是否需要多人房间。

正式直播不能套用文本 Token 单价。按实际供应商可验证的直播时长／生成任务成本 × 3 × 人民币换算 × Credit 汇率计量；开播前展示费率与预计可用时长，按小时间片预留并结算，余额不足自动结束。结束、心跳或重连不能重复扣费。Super 采用同一数值钱包，供应商费用依然发生。

本次仅完成消费端入口调整；远端 Vidu 桥接与真实 RTC 尚受服务器访问阻塞，真实时长计费也未启用。后续需先恢复桥接、核对平台正式费率和可信用量来源，再实现上述闭环。不得以浏览器传来的计时或价格作为账单，也不得将演练当成真实直播计费。
