# 叙梦会话备份

## 重新生成中刷新

2026-10-10 修复最新回复重新生成尚未收到有效正文时的刷新恢复（XM-096）。模型请求仍只使用旧回复之前的历史、有效摘要及世界状态；页面保存的原回复暂时保留，直到第一段包含非空白内容的新正文到达。准备请求时生成的前缀摘要暂存在本次操作里，不提前覆盖原会话的完整或部分有效摘要。

有效新正文到达后，以原历史前缀加新回复保存；匹配该前缀的新摘要一并应用，旧回复对应的世界快照失效。没有有效正文的结束、错误或停止优先恢复匹配原文的原摘要，原摘要无效时才使用新准备的有效前缀摘要。刷新继续沿用已有本地备份机制，不自动重新调用模型。历史回复重新生成仍建立独立分支，原会话不被替换。

7 条与 128 条会话的无正文挂起、长会话完成四次模拟摘要后的刷新均精确保留原文、摘要、世界状态和开场；完整生成与历史分支通过真实隔离 D1 保存。长会话有效部分正文后的刷新只取得浏览器未同步副本恢复证据，捕获时 D1 尚未同步该片段，不能算云端片段保存通过。25 项实际函数回归和 87 项相关逻辑回归通过，模型调用为零。Web 发布一次，版本 `f93e3c35-f938-4969-b169-64c0c372f440`；正式页核对当前资源，未注入生产私人会话故障。详见[本轮证据](../output/xumeng/iteration/heartbeat-20261010-chat-branches/round.json)。

## 输入草稿与待确认发送

2026-10-09（北京时间）聊天输入使用独立的 `xumeng-composer-drafts-v1:<accountId>` sessionStorage，按会话 ID 保存当前输入、失败原句与待确认请求的原文和编号。输入事件和发送前同步写入，保留空白、换行与 emoji，不进入云端故事状态、剧情记忆或模型正文。此缓存支持同一标签页刷新恢复；关闭标签页后的恢复不在其保证范围内。会话确认删除也会移除自己的输入草稿。

发送中刷新后，页面保留待确认原文和等待时的新输入，不自动重发。用户先核对会话结果，再显式恢复到输入框或移除待确认记录。这些按钮不发聊天请求、不操作余额。成功、错误或停止继续按现有回复规则处理，只有对应请求编号可以清掉待确认项。

缓存带版本和账号校验，整体最多 2 MiB，每条输入最多 12,000 字符，不截短文字。存储失败时保留当前输入和旧缓存，显示导出入口并保护离开。损坏缓存保留原始内容，导出同时包含新草稿与 `originalCache`，不会猜测格式后覆盖。页面故障验收使用完全截获的原创账号与模拟接口，真实模型调用、生产私人数据读取和真实余额变更均为 0。

会话导出保留全部原文，导入按文件字节大小和每条消息的有效性检查，不再限制为 200 条。导入重新生成角色、会话及消息 ID，按新消息 ID 重新绑定剧情记忆和世界快照；保留所选开场、世界时间模式和快照时间。损坏的可选记忆不应阻止有效原文恢复。

云端使用原有 256 KiB JSON 行分块，在同一次 D1 batch 中提交整次变更。不再把 500 条变更作为拒绝条件，也不将长历史拆成多次可能部分成功的 HTTP 保存。账户版本和事务 nonce 继续确保同版本竞争只有一个完整结果胜出。

容量边界仍存在：导入文件最多 2,000,000 UTF-8 字节，每条消息最多 12,000 字符；云端整个账户请求最多 2 MiB。文件符合导入大小不代表已有大量历史的账户一定能在此上限内同步。超限请求返回 413，保留本地记录与备份，并且不修改云端数据或版本。不会截短原文来伪造保存成功。

本轮验证覆盖 200、201、601 条导入与元数据绑定，501 条云端保存、601 条导入/分支、跨多个 JSON 分块的原文字节与顺序、超限拒绝和同版本并发。隔离验证不代表极限账户容量、真实模型剧情效果或支付验收。

相关代码：`src/lib/dzmm-conversation-backup.ts`、`src/components/dzmm/tavern-app.tsx`、`cloudflare/dzmm/src/data.ts`。隔离回归：`src/lib/dzmm-conversation-backup.test.mts`、`cloudflare/dzmm/test/conversation-backup.test.mjs`。

## 第二十二轮：异常回复与停止按钮保护

2026-10-08 用真实 TavernApp 和完全本地的原创地图员、园丁会话，确认并修复两个问题。纯换行回复会成为非法助手消息，云端等价校验拒绝保存；刷新读取本地备份时，又跳过整个会话。现在先积累原始流式文字，只有包含非空白正文才写入助手消息；错误或停止也按有效正文判断，恢复原输入或重生成前的旧答复、开场和世界快照。有效正文的前后空白、换行保持原样。当前生产网关已经提前拒绝纯空白生成，这次复现属于客户端异常响应防护，没有声称实际供应商生成了这种回复。

另一个问题是在等待期间输入下一句，再点击「停止」：同一按钮节点从普通停止按钮切换成提交按钮，触发第二次表单提交，把新草稿发送并清空。现在停止点击先取消默认动作，再中止请求；停止和发送使用独立 DOM 身份。真实本地点击复测中，空白停止、有效正文停止，以及回复恰好在按下／松开鼠标之间结束，都仅有一次表单提交与一次模拟聊天请求，新输入逐字保留。

九个最终明确返回通过结果的页面场景覆盖空白结束和错误后恢复、刷新保留；无有效正文的重生成恢复旧答复及世界／开场；上述三个停止场景；提交前 503 后重试、提交成功但响应丢失后继续编辑／冲突／加载云端／恢复本地，以及独立会话分支保存重开。早期脚本因警告文字匹配、菜单自动滚动关闭而中断，分别在已有页面继续取证，没有把 CLI 退出状态当成页面通过。

## 第二十三轮：多标签页恢复

2026-10-08 在同一个浏览器上下文的两个实际 TavernApp 页面中确认，同账号共用一条本地备份会覆盖未同步会话：一页写入另一页的内容后，刷新会丢掉本页分支。现在每个标签页保留账号对应的 sessionStorage 完整快照，未同步分支另存到独立的 `dzmm-cloud-recovery:<账号>:<writer>:<revision>`。每次更新先写入新版本，再只移除本写入者上一份准确内容；共享普通缓存只记录云端已确认的状态。旧恢复键保留兼容，不会静默自动合并冲突会话。

保存时标明当前副本是否未同步。干净但过期的标签页刷新后直接读取最新云端；真正未同步或旧格式状态不明确的副本继续保护。旧保存回包只更新对应云端状态，不能删除随后产生的新消息。恢复、加载云端、登录和退出前先保留被替换的未同步分支；浏览器存储失败则中止替换。

「我的」页面新增恢复版本选择、导出所选备份和确认删除。选项绑定完整账号和不可变版本，只删除明确选择的副本，当前未同步副本不能删除。严格校验拒绝身份自动补全、跳过会话等不完整修复，并统一字段顺序，避免无编辑页面重复提交。每账号恢复日志最多20份、合计8,000,000 UTF-8字节，单份最多2,500,000字节；浏览器实际配额可能更低。达到限制会提示导出和清理，不会自动淘汰其他分支。

## 第二十七轮：关联公开角色不可用时的历史

关联角色缺失的 `published-UUID` 会话仍保留在账号记录里，但原来消息侧栏会过滤它；从「我的 → 会话」打开也只显示空态。现在侧栏、标题和正文搜索仍能找到它，进入专门的只读历史面板，可以逐字查看、复制、导出或确认删除。手机端返回会话列表，删除不会切进别人的故事或清除其他会话的未发送草稿。整个账号的原有备份功能继续保留。

缺少角色卡时导出 `xumeng_conversation_archive_v1`：`character` 明确为 `null`，`conversation` 完整克隆保存的原文、原 ID、标题、开场和连续性元数据。它不猜测角色的人设、也不创建可聊天的替代卡。使用原有「导入会话」入口恢复时，重建独立会话和消息 ID，保留公开角色引用与原文，重新绑定有效世界快照、记忆及时间模式；可选元数据损坏不会删除正文。标题遵循现有持久化的 12,000 字符上限。普通含角色卡的会话文件继续走原导入器。

角色目录加载失败时，原文仍可只读访问。真实目录恢复同一个公开角色 ID 后，恢复普通聊天界面并沿用原历史。目录晚到使正在使用的角色消失时，关闭旧设置或编辑窗口，中止回复和建议请求；使用原有停止逻辑保留已收到的有效正文，无有效正文时恢复未发送输入。

只读存档导入仍受 2,000,000 UTF-8 字节和每条 12,000 字符限制，云端账户的整体容量限制不变。原文导出不截断；超限存档可以保存本地，但不能通过当前导入上限恢复。私人角色的明确删除仍按原确认流程删除关联会话，未更改其级联语义，也未放宽任意缺失私人 ID 的校验。
