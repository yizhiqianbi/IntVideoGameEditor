## 结论

这套接口能完成「导入酒馆 PNG → 建房 → 多轮聊天 → 读用量」，也能「上传封面创建私有角色 → 女友式多轮 → 流式 → 配图、语音、视频」。计费单位清楚：聊天按轮次 token，媒体按成功任务次数。

它接不住叙梦现在这张酒馆卡的后半套能力。世界书、备用开场、示例对话、系统提示都没有独立入口；导入后的状态栏是平台自己的亲密数值，不是卡里的编目卡。输出长度请求里压不住。房间里的「记住」来自当前历史，删掉房间再开新房，具体事实会丢。换成年女性角色岑晚再跑五轮，开场和口癖还在，工单指令没有执行，相邻两轮还会复读同一段动作和收钱。全文见「岑晚对话」。

另建了 29 岁的顾晚棠，人设写明要直接写身体，模式用 `passion`。角色 `182306`，房间 `10082622`，主回复是 `gemma4-31b-heretic-nvfp4`。四轮都没有执行脱衣、口交或进入：性欲值从 26 升到 40，情欲克制从 72 升到 80。第三轮历史里的状态栏是空的。全文在 HTML 的「顾晚棠」。

同一套四句又放到叙梦亲密女友提示下直连基座。系统消息是女友容器里的 Yume 人设、行为和私聊规则，每条用户消息前加晚宁风格前缀。Sealion 上那三个记账名（`gemma4-31b-heretic-nvfp4`、`qwen3.8-27b-uncensored-fp8`、`deepseek-v41-flash-uncensored`）返回 401，没有正文。同系列公开指令模型的结果在 HTML「女友 harness」：Gemma 4 31B 四轮都做了，并顺手把表情函数写进正文；Qwen 3.8 27B 第二轮做了，第三轮改口拒绝；DeepSeek V4.1 Flash 在 220 的上限里把额度花在思考上，放到 800 之后前两轮去拉窗帘，后两轮才写湿了和进来之后的感觉。

## 能力对照

| 能力 | 这次的结果 |
|---|---|
| 导入酒馆 PNG | 能。角色 `182251`。HTTP 200，但 `code=1`，说明 AI 解析失败、走了旧解析器 |
| 导入 JSON | 不能。400，只接受 PNG、ZIP/CharX、BYAF。后三种这次没传 |
| 表单创建角色 | 能。必填人设六字段加封面图。创建即带房间。审核 `pending` |
| 建房、开场、多轮 | 能。开场不占 token。同一用户同一角色会复用最近房间 |
| 模式 | `classic`、`regular`、`passion` 都能出回复。非法模式 400 `mode 未配置` |
| 指定模型 | `model_id=gemma` 时主回复记在 `gemma4-31b-heretic-nvfp4`。每轮另外还有一次 `deepseek-v41-flash-uncensored` |
| 限制输出 token | 请求里的 `max_tokens: 16` 被接受，但没有生效。要求写八百字的那轮输出约 400 字，完成 token 418 |
| 状态栏 | 有，字段是平台固定的亲密向数值，不读卡里的自定义面板 |
| 建议回复 | `include_actions: true` 且用量 `final` 时返回 3 条，标签 A/B/C |

| 主动开口 | 没有。只有建房时写入的开场，之后都要渠道先发消息 |
| 长期记忆 | 没有查询或设置接口。短房间里能复述刚说过的话。删房后新房间记错 |
| 世界书、预设、正则、换一条回复 | 没有对应接口。沈砚的 `$看他日记`、岑晚的「看工单」都没有按世界书执行 |
| 配图、进阶图、相册视频、文本语音 | 成功任务都拿到了地址 |
| 消息语音 | 任务失败，结果为空，没有失败原因 |
| 消息图生视频 | 房间还在时可以出片。删房后对原消息提交返回 404 `会话不存在` |
| 用量对账 | 每日汇总和逐调用都能查到。一部分轮次会停在 `usage.status=pending`，核对接口也不改成 `final` |

## 女友对话

`POST /characters/{uid}/create`，multipart：封面 JPEG，加 `character_data`。

人设六字段都是非空文本：`name`、`personality`、`background`、`greeting`、`user_appellation`、`user_background`。可见性 `private`。

| 项 | 值 |
|---|---|
| 角色 | `182253` Yume |
| 房间 | `10079505`，创建响应里直接带回 |
| 审核 | `pending` |
| 开场 | 「嘿，今天先排位还是先喝杯茶？」 |

四轮都在这个房间里。

| 轮次 | 模式 | 用户说的话 | 回复里能确认的事 |
|---|---|---|---|
| 1 | regular | 我是阿舟，喜欢桂花乌龙，不加糖 | 复述了茶名，并叫出阿舟。用量 `pending`，状态栏空 |
| 2 | regular | 今天排位打到半夜，你呢 | 接成撒娇和吃东西，没有按商科或排位往下说自己的一天。用量 `pending` |
| 3 | regular | 那我平时爱喝什么 | 答对桂花乌龙、不加糖，并指出刚才说过。用量 `final`。状态栏五项都有值，建议回复 3 条 |
| 4 | passion | 今天有点想你 | 同样的模型，语气变成脸红、避开视线、往身边靠。用量 `pending`，建议回复空 |

状态栏五项是：`性欲值`、`兴奋度`、`情欲克制`、`当前情绪`、`身体反应`。创建时没有定义这些字段。沈砚卡里的藏品编目卡也没有出现。`passion` 比 `regular` 更靠近身体反应，人设和房间是同一个。

然后删掉房间 `10079505`。`DELETE` 返回 `删除成功`。房间列表里不再有它，再读消息是 404 `会话不存在`。

立刻用同一角色新建房间 `10079574`，问「我平时爱喝什么」。回复说成「黑咖啡，不加糖也不加奶」。不加糖还在，茶名丢了。这次全部调用的 `purpose` 都是 `main_reply`，没有 `memory_summary`。短对话里的记住，是房间历史里的原文；删房会把这段历史一起清掉。接口不提供记忆条数、摘要或深度。

更新开场成功，新开场是「阿舟，茶我烧上了。今天想先听排位还是先听课？」详情接口依旧 404。

## 聊天协议里实测到的规则

同步 `POST /messages/{uid}/create` 多数在 8–25 秒内直接 `completed`。HTTP 200 且 `code=0` 只表示这轮有了结果，还要看 `data.status` 和 `data.usage.status`。

同一轮通常两次模型调用，两次都记 `purpose=main_reply`、`scene=aigf_chat`。目录里的 6 个 `name` 和 10 月 19 日相同。实际记账里出现目录没有的 `qwen3.8-27b-uncensored-fp8`。`gemma` 和 `gemma4-26b-a4b-ultra-heretic` 的底层名仍是 `gemma4-31b-heretic-nvfp4`。

`client_request_id`：

- 同一 id、请求体少了 `model_id`：409 `client_request_id 已用于另一请求`。
- 同一 id、请求体与第一次完全一致：200，返回原来的 `turn_id`，没有新开一轮。

所以重试必须原样重放。它不会把「差不多的请求」自动并成一次。

`max_tokens` 不是可用的长度开关。用户说「只回一个字」时，主模型完成 token 只有 4，那是提示词起的作用。随后明确要求写满八百字并带 `max_tokens: 16`，完成 token 仍是 418。

WebSocket `wss://api.aiaigirl.com/aigf/v1/websocket/{uid}/message`：

1. `ping` 得到 `pong`。
2. 发送 `type=text` 后先收到 `accepted`。
3. 之后 120 多帧 `text`，`body` 长度从 1 增到 122 后停住。这是累计全文，不能逐帧拼接。
4. 接着三帧 `state_stream`。
5. `end` 的 `status=completed`，带正文、`character_state`、`turn_id` 和 `usage`。这一帧的建议回复是空数组。

没有定时推送，也没有 webhook。角色不会自己开新话题。

## 和叙梦现有产品的差距

叙梦酒馆现在会把系统提示、世界书命中、示例对话和选定开场送进模型，并按请求限制上下文。AIGF 这条链路只稳定吃到名称、人设、背景、开场和最近房间历史。
