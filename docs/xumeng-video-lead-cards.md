# 叙梦 · 视频女主角角色卡：设计与评估

> 目标：视频频道里每部短剧的**女主角**，各自有一张可以聊天的角色卡；看完片的人能在片尾直接进卡。
> 本文给出：资产盘点、卡规格、生产管线、接入方式、量化评估、分批方案和红线。
> 盘点数据来自线上 catalog（2026-11-21 08:53 快照），脚本与产物见文末「已交付」。

## 0. 结论

1. **值得做，但不能整批做。** 线上 2017 部短剧里，只有 1133 部过得了机械筛选；其中 819 部是真人换脸/魔改，61 部题材踩线，这两类**先下架/去索引，不做卡**。
2. **产品链路已经铺好，缺的只是卡和 4 个字段。** 播放器已经有「片尾弹钩子 → 带角色进卡」的逻辑（`src/components/dzmm/video-channel.tsx` L804、L865-870），`hook` 结构也定义好了（`src/lib/xumeng-video-catalog.ts` L20-35、L78-83）。把 `hookCharacterId` 指到卡，链路就通了。
3. **建议节奏：先用自己的 3 条互动剧把闭环跑通并埋点，再用 20 张卡做 A/B，达标后才按 50 张/周扩。** 全量 1133 张卡约需 340–470 人时，不值得在没有转化证据前投入。
4. **卡的规格已落地**：沿用叙梦现有角色卡字段，加视频衍生扩展字段（`source` / `appearanceAnchors` / `rights` / `spoilerPolicy` / `qa`），三个备选开场对应片尾三个选项。校验器已跑通，示例卡通过。
5. **两条硬边界**：不为真人换脸/魔改做卡；不写露骨人设与系统提示。这两条既是我这边的工作边界，也正好是平台《社区公约》第 3、4 节的要求。

## 1. 为什么值得做：链路缺口在哪

视频频道是拉新入口，但看完一集短剧的人**没有下一步**：播放器结尾只有「下一集」，或者自动滑到下一条视频。已有的钩子能力只在 `互动剧` 分类或 catalog 显式带 `hook` 时触发，而线上 5889 条 items 里带 hook 字段的是 **0 条**。

现有代码的接入点（不用改协议，只填数据）：

| 位置 | 现有行为 |
| --- | --- |
| `src/lib/xumeng-video-catalog.ts` L20-35 | `XumengVideoDrama.hook = { title, body, action, characterId }` |
| 同上 L78-83 | 从 catalog item 读 `hookTitle / hookBody / hookAction / hookCharacterId` |
| 同上 L125 | `matchXumengVideoCharacter()`：先按 `characterId`，再按剧名匹配卡 |
| `video-channel.tsx` L223-227 | `storyTargetId` / `hookCharacter` 解析 |
| 同上 L804 | 最后一集播完 → 打开钩子弹窗，不自动滑走 |
| 同上 L865-870 | 弹窗按钮目标 = `hook.characterId || 匹配到的卡` |

也就是说：**卡存在 + catalog 补 4 个字段 = 片尾多一条「换你来选」的入口**。剩下的是内容生产问题。

## 2. 资产盘点（线上快照，2026-11-21 08:53）

> catalog 是活文件，每次重跑脚本数字都会变；本文数字以这次快照为准。

| 分类 | 部数 | 集数 |
| --- | ---: | ---: |
| AI成人短剧 | 1128 | 4703 |
| AI成人漫剧 | 82 | 379 |
| AI魔改 | 446 | 446 |
| AI换脸 | 361 | 361 |
| **合计** | **2017** | **5889** |

按「能不能做卡」三分类（脚本输出）：

| 状态 | 部数 | 说明 |
| --- | ---: | --- |
| `eligible` 可做卡 | **1133** | 通过机械筛选，仍需人工复审 |
| `excluded_real_person` | **819** | 真人换脸/魔改，红线 |
| `excluded_content_risk` | **61** | 未成年/非自愿/乱伦题材，不做卡 |
| `duplicate` | 4 | 同名重复，只保留集数多的一部 |

可做池：1133 部 / 4721 集。**但这不等于「应该做 1133 张」：**

- 其中 97 部标题带露骨广告词，卡名/封面必须另起，不能照搬剧名；
- 319 部是单集短片（更适合做「一张卡 + 一条视频」，而不是连载卡）；
- 814 部是多集剧，单集时长从 30 秒到 28 分钟都有（抽样 10 集：均值约 470 秒，最短 30 秒，最长 1676 秒），一卡需要抽 4–8 集做样本；
- 真正适合做卡的是「人物有辨识度、关系有张力、完播率高」的那部分，经验上不超过可做池的 20–30%。

真人识别的做法（脚本里已实现，不依赖任何内置姓名表）：

1. `AI换脸` / `AI魔改` 两个分类直接判死（807 部）；
2. 从这两个分类的标题里正则提取 2–4 字人名候选（用常见姓氏过滤），得到 207 个候选；
3. 用这批候选回扫其它分类的标题，又抓出 12 部漏网的真人条目；
4. 剩下「AI成人短剧」里仍可能有真人混入，靠分类名和标题抓不全，发布前必须再过一遍人工/人脸相似度。

## 3. 角色卡规格

### 3.1 复用叙梦现有卡字段

卡的字段不用另造，直接用平台现在这套（与 `output/xumeng/daily-drama/*-card.json` 一致，解析器见 `src/lib/dzmm-character-context.ts`）：

| 字段 | 必填 | 用途 | 上限 |
| --- | --- | --- | --- |
| `name` | ✅ | 卡片货架标题（带女主名字便于搜索）；女主本名写进 `description` | 平台上限 120 字 |
| `author` | ✅ | 作者/署名 | — |
| `description` | ✅ | 她是谁、在哪、和你什么关系 | 15000 字 |
| `personality` | ✅ | 说话方式、矛盾、底线 | 15000 字 |
| `scenario` | ✅ | 视频结尾那一刻的场所与状态 | 15000 字 |
| `systemPrompt` | ✅ | 扮演规则、边界、不剧透 | 15000 字 |
| `firstMessage` | ✅ | 接在视频最后一幕之后 | 15000 字 |
| `alternateGreetings` | ✅ | **正好 3 条**，对应片尾 3 个选项 | 20 条 |
| `suggestedReplies` | ✅ | 3 条快捷回复 | — |
| `postHistoryInstructions` | 建议 | 连续性、不替用户决定 | 15000 字 |
| `messageExamples` | 建议 | 2–3 组对话示范语气 | 15000 字 |
| `characterBook` | 建议 | 场景/人物/规则世界书，不写结局 | 5 MB 总卡 |
| `introduction` | 建议 | 卡面一句介绍 | 15000 字 |
| `tags` | 建议 | 最多 **6** 个 | 6 个 |

### 3.2 视频衍生扩展字段（新加，解析器会忽略，不破坏兼容）

```jsonc
{
  "source": { "origin": "video", "dramaId": "hg-4172", "episodeCount": 60,
              "posterKey": "posters/huangguo/4172.jpg" },
  "appearanceAnchors": {          // 脸/发型/服装/体态/辨识点/音色，全部来自视频帧
    "coverFrame": "…9x16.jpg", "faceCrop": "…face.jpg",
    "hair": "…", "outfit": "…", "body": "…", "signature": "…", "voice": "…"
  },
  "rights": { "license": "unknown", "realPerson": false,
              "clearance": "pending", "evidence": "" },
  "spoilerPolicy": { "maxEpisode": 1, "noEnding": true },
  "qa": { "status": "draft", "reviewer": "", "checkedAt": "", "checklist": [] }
}
```

- `appearanceAnchors` 是**封面与后续生成的一致性锚点**，封面必须从视频帧裁，不要重新生图，避免「卡脸和片子不是同一个人」。
- `rights` 是发布闸门：`realPerson` 必须显式为 `false`，`clearance` 不为 `cleared` 只能当草稿。
- `spoilerPolicy.noEnding` 必须为 `true`：卡是「视频之后」，不是剧情梗概。

### 3.3 写卡四条硬规则

1. **成年虚构**：卡内明确成年，不写未成年、幼态、学生设定；不出现现实人物姓名与形象。
2. **我产出的部分是剧情向**：卡面、简介、标签、系统提示不写露骨性描写，亲密感靠停顿、距离、信任。公开卡面/标题也不能露骨（《社区公约》2.2）。需要成人向正文时，由平台自己的编辑与审核链路补充，我不代写。
3. **不剧透**：卡只承接「视频最后一幕之后」，不写结局、反转、凶手。
4. **三个开场 = 片尾三个选项**：用户在视频里选的哪条，进卡就是哪条的第一句；这样「选择」才有连续感。

一份通过校验的完整示例（虚构原创剧《雨夜琴房》，非露骨、非真人）：
`output/xumeng/lead-card-triage/examples/example-card.json`。

## 4. 生产管线（5 步，3 个人审点）

```text
catalog ──S1 选片──▶ 候选剧 ──S2 抽帧定女主──▶ 锚点图 + 宫格
      ──S3 写人设草稿──▶ 卡草稿 ──S4 组装──▶ 成卡 ──S5 校验/接入──▶ 上线
```

| 步 | 做什么 | 工具/落点 | 人审点 | 产出 |
| --- | --- | --- | --- | --- |
| S1 选片 | 分类、去重、真人/题材筛除、排序 | `scripts/xumeng-lead-card-triage.mjs`，读线上 catalog | 是 | `worklist.csv`、`skeletons/` |
| S2 抽帧定女主 | 每集均匀抽帧 + 场景切换，拼 9–12 宫格；同一张脸在 ≥3 个镜头出现才算女主 | `ffmpeg`（本机 9.0.2 可用）；多女剧按首个主视角 | 是 | `appearanceAnchors`、封面 9:16、宫格 |
| S3 写人设 | 宫格 + 字幕/ASR → 身份/性格/关系张力/说话方式/世界观草稿 | 多模态模型出草稿（vision），或人工；平台现有 `sealion-nova-pro` 通道可用于人脸/年龄复核 | 是 | `card.*` 草稿 |
| S4 组装 | 填模板；三选项 → `alternateGreetings` + `suggestedReplies`；世界书只放场景/人物/规则 | `card-template.json` | — | 成卡 JSON |
| S5 校验/接入 | 过校验器；补 catalog 的 `hook*`/`characterId`；走发布流程 | `--validate`；hook overlay（见 §5） | 是 | 上线卡 + 钩子 |

抽帧命令（每集约 8–12 帧，够判断女主和服装）：

```sh
ffmpeg -i "$MEDIA" -vf "fps=1/20,scale=360:-1,tile=4x3" -frames:v 1 "sheet-%02d.jpg"
```

## 5. 接入产品

**不要直接改 catalog 生成器。** `cloudflare/video-web/public/catalog.json` 是从素材清单重新生成的（见 `build_full_catalog.py` 一类的脚本），手写的 hook 字段一重跑就没了。建议加一层 **hook overlay**：

```jsonc
// cloudflare/video-web/public/video-hooks.json（新文件，按 dramaId 覆盖）
{
  "hg-4172": {
    "characterId": "…",
    "hookTitle": "她知道你选了哪条路",
    "hookBody": "换你来选：留下、问清楚，还是转身走？",
    "hookAction": "进入她的故事"
  }
}
```

模板：`output/xumeng/lead-card-triage/hooks-template.json`。读取端把 overlay 合进 `parseXumengVideoCatalog` 的结果即可（`xumeng-video-catalog.ts` L78-99 已经是合并逻辑）。

播放器侧不用改：最后一集 `onEnded` 检测到 `hook` 就弹「换你来选」（L804），按钮直接 `onOpenStory(characterId)`（L870）。**要确认的只有埋点**：钩子曝光、选项点击、进卡、首条消息四个事件。

搜索别名：如果卡名不是剧名（多数情况），只能靠 `hookCharacterId` 精确指定；`matchXumengVideoCharacter` 的标题兜底只在卡名≈剧名时有效。

## 6. 评估

### 6.1 工作量与成本

假设：每卡覆盖 4 集（4 张宫格）+ 1 次人设生成 + 1 次封面锚点裁切；模型单价按现有通道量级估（视觉 call $0.005–0.02，文本 call $0.001–0.003，封面 $0.02–0.05）。

| 项 | 每卡 | Top 100 | 全量 1133 |
| --- | --- | ---: | ---: |
| 模型调用 | ~6 次 | ~600 次 | ~6,800 次 |
| 模型成本（估） | ¥0.4–0.9 | ¥40–90 | ¥450–1,000 |
| 人工（抽帧 + 写卡 + 校验） | 18–25 min | 30–42 h | 340–470 h |
| 日历时间（2 人并行） | — | 3–5 天 | 9–12 周 |

结论：**成本大头是人工，不是模型。** 所以优先级是「选对剧」，不是「买便宜模型」。

### 6.2 质量风险

| 风险 | 表现 | 处理 |
| --- | --- | --- |
| 认错女主 | 群像/多女剧里选错人 | 同一张脸 ≥3 镜头；首视角优先；人工确认 |
| 同脸多剧 | AI 短剧复用同一张脸，两张卡像同一个人 | 跨剧人脸聚类，同脸只做一张或明确「同一演员不同角色」 |
| 身份漂移 | 封面脸与视频脸不一致 | 封面只从视频帧裁；`face-lock` 复核 |
| 年龄边界 | 18/19 岁、幼态脸 | 卡内写明成年（建议 ≥22），封面不用幼态脸 |
| 真人泄漏 | 分类外的真人条目 | 姓名回扫（已抓 12 部）+ 人工 + 人脸相似度 |
| 剧透 | 把结局写进卡 | `spoilerPolicy.noEnding`，校验器强制 |
| 语气错位 | 把片中性情节写成角色默认行为 | 关系起点 + 三选项；卡不含露骨情节 |
| 维护 | 剧集下架/更新、卡与片脱节 | 卡绑 `source.dramaId`；下架联动下线卡 |
| 审核容量 | 100+ 张卡同时进公开目录 | 分批提审，先草稿/私有，A/B 后再公开 |

### 6.3 法律与合规（这一节是「先别全做」的主要理由）

| 问题 | 规模 | 判断 |
| --- | ---: | --- |
| 真人换脸/魔改 | **819 部** | 与平台《社区公约》3.3「涉及真实人物形象和声音，须先取得适当许可」、4.1「不得传播真实的非自愿私密影像」直接冲突；民法典肖像权/声音权益、深度合成规定也要求授权与标识。**这些不是「做卡」的对象，是应下架的对象。** |
| 第三方成人内容 | 1210 部 | catalog 标注「黄果公开HLS授权导入」，这个说法只覆盖**播放**，不自动覆盖**改编成角色卡**。需要逐系列或一揽子的改编书面授权，否则卡就是二次使用。 |
| 卡面/卡名 | 全部 | 公约 2.2：公开封面、标题不得含露骨性描写。所以卡名要另起，封面用非露骨帧。 |
| 年龄与门槛 | 全部 | 平台面向 18+；卡必须写明成年。 |

一句话：**真人那 819 部先处理掉，比做 100 张卡更紧急。**

### 6.4 产品指标与止损线

| 指标 | 口径 | 目标（先验假设，跑完校准） |
| --- | --- | ---: |
| 钩子曝光 → 选项点击 | 片尾弹窗 | ≥ 15% |
| 选项点击 → 进卡 | 带第一条消息 | ≥ 60% |
| 进卡 → 首条消息 | 用户真的开口 | ≥ 50% |
| D1 回访 / 7 日留存 | 进卡用户 | 与站内平均持平或更好 |
| 付费转化 | 进卡用户 | 不低于站内平均 |

止损：**选项点击 < 8%，或进卡后首条消息 < 30%，停掉批量计划**，回去改钩子文案/选项设计，而不是继续加卡。

### 6.5 ROI 判断

- 一张卡的人工约 20 分钟，换来一条视频的长期转化入口；如果一部剧日均播放能到几百次，这笔投入是划算的。
- 但对长尾剧（大部分播放极低），做卡是净亏。**Top 100 覆盖的播放量通常已经是大头**，不要平均用力。
- 卡还能复用：同一女主的多部剧可以共用一张卡（改 `source` 指向多部剧），这是降低工作量的关键杠杆。

### 6.6 局限与未验证

- **没有逐部看片**：女主识别、同脸复用程度、ASR/字幕可用性都没有实测；本文所有数字来自 catalog 元数据 + 10 集时长抽样。
- **时长抽样只有 10 集**，均值 470 秒波动很大（30 秒到 28 分钟），实际排期要按目标剧重新抽样。
- **模型单价是量级估计**，没有用真实账单核对；正式预算前先跑 3 张卡记账。
- **真人漏网率未知**：分类 + 标题回扫只能抓已知模式，剩下必须靠人工/人脸相似度。
- **播放/完播数据未接入**：Top 剧排序需要产品侧提供播放数据，脚本现在按集数排序，只是占位。

## 8. 红线（这部分我不会做）

- **不为 819 部真人换脸/魔改做卡**，也不为它们写任何角色设定。
- **不写露骨人设、露骨开场和露骨系统提示**。我交付的模板和示例保持剧情向；成人向正文由平台自己的编辑/审核链路补，不在这套交付里。
- **不批量自动发布**：所有卡必须过人审 + 校验器 + 版权/真人核验才能公开。
- **不用真实姓名、真人肖像、真人声音**做卡名、封面或音色。
