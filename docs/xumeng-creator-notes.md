# 角色正文与作者备注

2026-10-08：叙梦角色详情、列表摘要、创作预览和已识别的开场分开展示故事正文与作者备注。原始导入资料、公开资料哈希、已有会话原文保持完整。

## 数据

`creatorNotes` 是独立展示字段，兼容角色卡 `creator_notes`，最多 12,000 字，保留原始空白。编辑器可以单独编辑、清空；私人云端状态、D1 `context_json`、审核快照和公开卡均保留。无需数据库迁移，前后端 Worker 必须一起发布。导出同时保留标准字段及来源说明，重复导入导出不叠加来源说明。此字段不在模型请求白名单内。

## 混合文本的派生展示

`src/lib/dzmm-character-presentation.ts` 为纯函数。只识别独立的封面绘图致谢、明确作者备注标题，以及含角色卡测试模型、更新或反馈线索的 PS 段。正文、段落、书信署名、占位符均保留；仅规范显示层复制时的 CR + 反斜线 + LF 分隔符。

普通书信 PS、引号内的作者字样、跨行对白、代码围栏及缩进代码不做作者注推断。无法确定的文字留在正文中，作者可用独立备注字段明确区分。备注默认折叠，详情及开场可展开查看。普通生成回复与用户消息不自动重分类。

用户给出的龙漓例子：顶部「感谢…跑图」和末尾含模型测试、二次修改、反馈的 PS 为作者备注；从「我，南海龙王最小的女儿」到署名及「才不是离家出走」为正文。

## 对话与记忆

缺省开场派生自场景或简介的正文；只有备注时采用普通欢迎语。简介与开场混入的明确作者备注不进入模型角色资料或开场历史。人物性格、场景和显式系统指令作为结构化创作设定保留，不能用展示启发式删除作者的真实指令。

只投影与角色卡或固定开场快照匹配的历史前缀，未知、被用户实质编辑的聊天原文仍是实际历史。旧会话识别后固定原始开场快照，确保刷新、重复恢复和开场变更不会重新插入错误的主场景。

摘要使用同一开场投影，覆盖索引及指纹仍依据原始消息。纯备注消息的省略不算历史截断，不会产生多余付费摘要；纯备注批次可以继承既有事实或空状态，在本地推进覆盖。已有模型生成的语义摘要不自动改写。

## 证据

`output/xumeng/creator-notes/` 保存源码哈希、纯函数与记忆回归、实际本地 UI、原生存储清理、隔离 D1/R2 API 和生产资源检查。浏览器用两张自有普通原创私人卡；模型回复使用本地假接口。本轮真实模型、付款、签到和公开投稿均为 0。

参考页面提供了「作品详情」独立信息面板的阅读方式；未观察到其自动识别作者注或模型排除机制，因此没有将这些行为视为参考站已实现的能力。
