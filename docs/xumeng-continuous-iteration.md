## 执行与边界

- 浏览器先检查已有连接和可用标签页，遵循 Browser 技能。子代理连接不可用则由根代理接手；一次合理恢复后仍失败，就记录 UI 验证受阻，继续独立的本地工作，不重复重连。
- 并行代理的产物指定独立子目录或具体文件名，根代理保留台账及本轮基线文件的所有权。钱包快照轮次的夹具代理复用了 `preflight.json`，覆盖了根代理的初始基线；保留夹具原证据并记录初始基线缺失，不能用事后快照冒充事前检查。交接服务同时给出进程 PID、命令及安全停止方式；代理创建的终端 session 可能不能由根代理继续操作，核对自有 PID 后停止并确认端口关闭。
- 使用自己创建的普通原创、私人测试角色和会话。测试前记录当前数据数量，创建后记录本轮测试对象的名称和 ID；前一轮的数量可能已过期，不能用它推断删除对象。已有标签页的上次同步提示也不能证明本轮数据最新：开始写入前，在保留未保存修改后刷新目标页面，等当前账号同步完成，再记录基线。不要读取原有私人会话来充当测试材料；只按本轮对象身份清理，刷新核对测试对象已消失。有其他用户活动时保留数量变化的事实和限制。
- 隔离测试覆盖付款回调、并发签到和扣费等。正式站不执行真实支付、真实账户签到、公开投稿或改价格，不启用聊天扣费。需要实际付费验收时留下具体待办。
- 正式账户无法安全构造的失败场景，用真实产品组件和完全本地的模拟接口验收；模拟服务的日志与产品提示分别取证，错误提示必须检查产品区域，不能把控制台中留下的错误文字算作界面通过。区分模拟签到 POST 与正式签到，模拟成功不能证明真实付款或权益发放。
- 故障模拟先核对真实客户端的请求方法、路径及返回格式，再设置挂起或失败；未命中模拟端点的拒绝响应不能算产品故障复现。第九轮媒体挂起最初使用错误路径，修正模拟接口并固定版本后才完成验收。
- 时间模式等下拉设置操作后先核对实际选中值，再推进模拟时间或执行依赖动作。第十轮最初使用方向键没有改变选择；重置场景、明确选择并核对后才取得有效暂停复现，避免把未生效的设置当成缺陷证据。
- 验收失败恢复前固定产品和模拟接口版本；开发热更新会重挂载组件，不能将热更新引起的第二次成功读取算作用户重试成功。优先持续故障 → 仅恢复服务 → 产品重试，并等待模拟计数更新后记录。媒体恢复须检查实际文件读取及原生音频元数据/图片尺寸，目录接口成功不足以证明文件恢复。同一原生媒体URL可能沿用浏览器已有缓存，即使服务器故障已开启；必须核对新的文件请求和失败计数，未命中服务端不算失败复现。本地场景可在启动时给素材ID加入固定轮次标识，并在首次文件读取前设置故障，验收中途不改ID。
- 涉及数据库与文件存储的提交或清理时，分开验收“提交前失败”和“实际提交后响应丢失”。错误响应不能证明数据未提交；清理需要核对持久引用，查询也失败时保留未知对象。加入并发赢家及历史快照读取验收，避免恢复逻辑误删仍可合法访问的文件（第六轮审核故障依据）。
- 每轮原则上不用外部模型；只有相关行为改变确实需要验证时，最多两次普通文本调用并记录。媒体实际生成另列必要性和用量。避免重复消耗。
- 涉及跨服务计费配置时，独立检查网关实际请求的供应商上限与后端冻结政策是否一致；验证缺配置和超过上限会在模型前拒绝并释放已经建立的预留。标准 Token 价格不能代替实际美元费用，生产开关／页面显示与真实扣款各自取证（第十二轮跨层审查依据）。
- 新增生成预算或报价步骤时，发布前覆盖收费开启/明确关闭与正式账户/游客的组合，并用真实组件和数据库核对最终模型上限、请求指纹、原子预留。第十六轮遗漏了关闭计费的真实游客报价，首次发布后才发现兼容回归；报价通过不等于已授权生成，供应商返回的实际用量也需与请求上限分开记录。
- 报价与生成之间的政策变化要同时验收服务器和页面：409 应在预留前拒绝，页面保留描述并恢复可点击的“查看本次报价”。不能只验证服务器拒绝就认定完整恢复；报价失效与提交响应丢失要分开，后者必须保持原请求编号而不自动重投（2026-10-08 生图/视频工作台补查依据）。
- 费用补查必须覆盖请求模型别名与官方目录中的 canonical_slug。第十七轮复用已有原创生成编号发现，合法的带日期模型名被严格字符串比较拒绝；仅通过独立官方目录验证的映射可兼容，不能通用去日期或按前缀匹配。先只读查询已有样本再决定是否新生成，分别记录原生总输出、推理和归一化 Token，不能叠加或互换。
- 原有浏览器面板受阻但出现新的可用工具时，可用新建的隔离浏览器完成本地原创夹具验收，并明确区分生产页面。原生文件选择、刷新离开确认会中断批量操作；拆开处理弹窗，重新读取实际编辑器并核对账号、内容和模拟请求计数。CLI 返回空对象或进程成功退出不能算验收成功，必须取得显式断言和结果。第十八轮文件选择中断及另存后回到设置页造成脚本漏读，均在重新选择文件／章节、核对实际内容后才记为通过。
- 涉及另存副本和恢复清理时，同时验收「失败后原样重试」与「失败后改稿再重试」。核对只存在于原未保存稿的文字或章节，仍能在实际恢复副本或已保存作品中找到；保存成功响应不能证明原稿安全。第十九轮独立审查后实际复现了候选修复在副本改写后误清原完整稿，撤销清理关联后两条路径分别复测，发布前固定最终源码。
- 涉及切换账号／注销后的后台资源回收，必须同时改变 Cookie 与界面身份，等待成功响应中的明确结束标志并核对实际资源池或配额，不能只计数 DELETE 请求次数。覆盖旧创建回包晚到、连续切换、注销及旧回收令牌误用在新资源上的拒绝。本次 Vidu 接入先前代码审查与请求计数漏掉旧 Cookie 已失效的删除，导致两个租约名额耗尽；现以 `200 + ended:true` 和资源池数量作为验收依据。
- 文件导入需用实际字节验证编码与尺寸；界面显示成功不能证明正文完整。长 TXT 验收同时核对章节拼接、空白、跨章 emoji、保存重开和下载文件字节。AI 预览单独验收停止／中断、目标章删除、导出、插入及限额失败；只验证原稿不被自动覆盖会漏掉预览自身丢失。第二十轮分别复现了非 UTF-8 乱码和删除目标章清空预览，修复后用原创文件及本地流式夹具闭环。
- 导航保护除了正常菜单，还要验收「干净工作台 → 无法解析的路由但页面未变 → 修改正文 → hash 离开」。第二十一轮在正式页面确认，未知角色地址误清工作台标记，随后可绕过脏稿保护；只有成功解析并实际切换的路由才能更新页面保护标记。
- 清理以对象消失、关联行计数和原生浏览器持久数据为依据。模拟 Storage 的 `Object.keys()` 可能枚举 API 方法；D1 删除的 `meta.changes` 可能包括会话级联，不能要求它等于一个用户行。第二十一轮两处清理断言误报后，分别核对原生存储和精确测试账号的只读计数；删除结果已提交时不重复 DELETE。
- 流式故障验收检查可见消息、本地原始备份、实际持久化解析和刷新重开，覆盖纯空白结束／错误／停止及有效部分正文。模拟保存必须采用与后端相同的内容校验；仅检查 messages 是数组会掩盖非法消息。第二十二轮确认空白助手消息使整个会话在刷新解析时被跳过，生产网关虽已有前置保护，客户端仍需防御异常响应；两层证据分别记录。
- 停止回复需在等待期间输入下一句，检查表单提交次数、聊天请求次数及草稿原文，不只检查停止图标消失；另覆盖服务响应发生在按下与松开鼠标之间。第二十二轮实际观察到停止按钮被复用为提交按钮，一次停止误发新草稿；修复默认动作和按钮身份后，这些场景均保持一次请求。
