# 叙梦玩家委托

入口是 `/#tasks`。任务中心默认展示「新手任务」，用双列卡片引导用户完成个人介绍、首次对话、关注作者、论坛互动和角色发布；「玩家委托」仍可切换查看。新手任务与委托奖励直接记入统一聊天 Credit 钱包，可用于聊天与记忆消费。

## 使用流程

1. 正式用户填写标题、任务说明、验收要求，可补充独立任务目标、约束标签和编号规则，选择角色体验／原创写作／意见反馈，可关联已上架的公开角色。
2. 奖励支持每人 5、10、20 Credit，名额 1–20 人，页面提供 12／24／48 小时期限。提交后进入待审核；只有 Super 的平台审核通过，任务才开放领取。管理员可审核自己的委托，但发布者不能领取自己发布的任务。
3. 领取成功占用一个名额。“我领取的”展示本账号领取的任务及历史进度，“我发布的”展示本人发布的委托。撤回、到期或验收后仍可从领取列表找回记录；隐藏的记录在“已隐藏”恢复。参与者提交自己的原创文本成果；作品不自动读取私人会话。发布者和参与者本人可以查看提交记录，平台管理员可进行管理；其他用户只能看到任务说明和汇总数量。
4. 发布者验收通过，服务端自动发放一次 Credit；退回需写明原因，参与者在原截止时间前可再次提交。
5. 发布者取消任务会停止新领取，已有参与者仍保留原截止时间内的提交权。已提交的成果在截止或取消后仍可验收，已发奖励保留。参与者主动退出会释放名额，该账号不能重复领取同一任务。
6. 「不再显示」只影响本人的列表，可在「已隐藏」恢复。未审核、被拒绝的任务不会因隐藏或取消变成公开任务。

## 数据和接口

Cloudflare D1 的 `0026_task_market.sql` 创建任务、领取、提交版本、审核记录、奖励和个人隐藏六张表。API 统一走网站同源 `/api/backend/v1/task-market` 网关，后端为 `/v1/task-market`，使用现有 Cookie 会话及 Origin 校验。

- `GET /`：状态、分类、搜索、分页；`filter=joined` 为当前账号任意领取状态的未隐藏记录，`filter=my` 为本人发布；`GET /:id`：详情和有权读取的成果。
- `POST /`：发布待审核任务，`accountId + requestId` 固定重试身份和内容指纹。
- `POST /:id/claim|hide|cancel|withdraw|submissions`：领取、个人隐藏、取消、退出、提交。
- `GET /admin`、`POST /:id/review`：Super 平台审核。
- `POST /:id/assignments/:assignmentId/review`：发布者验收或退回。

修改请求明确绑定账号；任务／领取版本控制拒绝过期操作。领取名额和资格在同一 SQL 写入内检查。验收状态、审核记录和唯一奖励流水在 D1 batch 事务中提交，奖励以领取编号为唯一键，重复请求不重复发奖。平台审核冻结奖励和名额，不接受客户端伪造权限、积分或完成状态。

客户端读取和修改请求共用 20 秒期限，包含连接和响应正文读取。超时会中止请求并解除页面等待；写请求超时表示结果尚未确认，应先刷新状态，客户端不会自动重复写入。提交回包丢失时原稿仍保留，服务端版本检查避免重复提交。

既有 `task_claims`、`task_market_rewards` 和邀请奖励会幂等投影到统一 Credit 钱包；固定平台任务的完成条件和领取历史保持原逻辑，合并后的 Credit 到账后长期有效。

## 验收边界

数据库流程用临时真实 D1 运行，页面用自己的普通原创夹具验收。正式网页检查当前发布资源和真实组件，但业务接口使用隔离模拟，不在正式站公开测试任务、发奖或读取原有私人会话。实际玩家使用和平台审核是上线后的业务行为，不把模拟页面验收当成真实奖项发放。

## 任务目标与约束

发布页提供可选的结构化内容：`instructions = { goal, constraints, rules }`。目标最长 4,000 字；约束最多 10 条、每条 120 字；编号规则最多 20 条、每条 500 字；合计最多 12,000 字。规则支持上移、下移和删除，顺序在保存及展示中保持一致。内容按纯文本显示，保留换行，不执行 HTML。未填写目标时，详情页用原任务说明作为「任务目标」；有独立目标时，原说明展示为「任务背景」。约束标签和编号规则仅在有内容时展示。

迁移 `0027_task_market_instructions.sql` 增加 `instructions_json` 列，旧任务默认空结构，原文和原发布指纹不回填或重写。旧客户端省略该字段、新客户端发送全空结构，都保持原八字段请求指纹。非空结构加入内容指纹；同编号变更内容或规则顺序返回 409。编辑器空白条目保留在浏览器草稿，发布时只过滤空白条目，不裁剪有意义的文字。发布状态不确定时，整个编辑器锁定，刷新后仍使用原请求编号、期限及结构原样重试。旧草稿与旧冻结请求保留省略字段的原格式。

这些字段供创作、领取前阅读及人工验收使用。它们不自动读取私人会话、累计对话句数、跳转剧情阶段或判定角色状态；任务领取、提交和验收发奖沿用既有流程。
