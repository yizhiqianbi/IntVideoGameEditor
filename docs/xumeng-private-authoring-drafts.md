# 私人未完成世界书草稿

世界书只写了名称、关键词或内容时，作者可以保存私人草稿，退出、刷新或同步后继续编辑。默认全空且未改设置的占位条目仍会略过；已有文字、词条顺序和设置不会静默丢弃。

## 保存与使用

私人角色单独保存 `authoringDraft`（版本 1）。它保留原始关键词输入、辅助关键词、条目内容和设置。`characterBook` 继续经过正式角色卡解析，仅包含已完整条目，运行请求不包含私人创作数据。编辑器、角色详情和已有会话发送入口会阻止未完成角色试聊，公开提交也会拒绝未完成草稿。

所有条目完善后，保存、直接试聊或提交前的私人保存明确使用 `authoringDraft: null`，清除旧标记。公开请求会剔除该字段。无需更改数据库表：私人草稿独立保存在已有 `context_json` 内，公开角色及历史审核快照的读取不包含它。

旧客户端全量同步未带这个字段时，服务端保留已有草稿；若同时改动运行世界书，拒绝冲突更新并提示刷新。明确的 null 表示作者已完成或移除未完成内容。损坏的可选草稿在本地恢复时显示警告并保留有效角色和历史，服务器拒绝带警告的写入。

## 保存失败后恢复

云端保存失败后，创作页提供“重新同步并保存”，退出确认也提供“重新同步并保存后退出”。这两个入口重新构建当前编辑稿，包含失败后新增的文字和未完成世界书，再按原账号、原云端版本恢复保存。完整成功后才清除未保存状态；持续失败时保留当前编辑稿和本地备份。

恢复期间不能重复操作或离开。登录会话变成其他账号时，在读取该账号记录前停止；其他标签页改变云端版本时拒绝覆盖，并保留具体冲突提示。此入口不自动合并冲突，也不强制加载云端；有冲突时可以先导出当前稿件，再选择保留的版本。

这些交互采用真实组件、原生浏览器存储和本地隔离接口验收；上线资源的字节与构建结果另行核对，未使用原有私人会话或外部模型。证据见 `output/xumeng/iteration/rounds/round24-20261008.json`。

## 文件边界

未完成角色导出为 `*.draft.json`，标记 `xumeng_authoring_draft_v1`，包含正式角色部分和私人创作数据；导入后回到编辑器。普通角色卡导出及普通会话导出不包含未完成创作文字，普通角色卡解析仍要求有效的完整世界书。账户备份属于私人完整记录，可以包含创作草稿。

沿用正式条目数量和内容上限：最多 200 条，每条内容 8000 字；私人草稿及角色总量按 UTF-8 限制为 256 KiB，文件也不得超过 256 KiB。超限会显示错误，不会截断作者文字。

## 本轮验收

本地恢复与文件往返、真实请求组装的创作数据隔离、隔离 D1/API 持久化与旧客户端兼容，以及正式网页保存/刷新/重新同步/补全后直接试聊分别记录。实际验收和版本见 `output/xumeng/iteration/rounds/round3-20261006.json`；没有调用外部模型或执行付款。

## 注册与已有账号登录

角色编辑器的“注册或登录”会先保存当前有修改的私人草稿，只有云端确认成功才打开账号窗口。校验或同步失败时原文和当前编辑器保留，可通过“重新同步并保存”恢复。进行中的创作操作、未保存角色和账号切换也受到统一保护。首次游客会话创建失败时，仍允许从登录入口恢复已有账号。

新账号注册沿用游客身份并保留已保存记录。登录已有账号会加载该账号自己的记录，不自动合并游客角色；需要继续创作当前角色时，先用“导出”下载角色卡，登录后创建角色并“导入”。未完成的世界书以私人创作草稿文件导出，正文、开场和作者备注一并保留。

本轮证据：`output/xumeng/iteration/rounds/round25-before.json`、`round25-after-ui.json`、`round25-final-guard.json` 与 `round25-no-session-after.json`。失败和身份迁移矩阵使用真实组件、原生存储和本地 HttpOnly Cookie/CAS 接口；生产部署以完整构建资源字节和网页展示另行验证，不将本地模拟认证记为生产邮箱或交易验收。
