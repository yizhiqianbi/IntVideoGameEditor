# 叙梦游戏创作

本轮采用 Browser Instant：单文件 HTML、CSS、JavaScript 的私人创作工作台。入口在创作中心，`#studio/games` 查看自己的作品，`#studio/games/new` 创建，`#studio/games/:id` 继续编辑。游戏开发目前提供真实源码编辑、试玩、导入、备份和云端保存；不提供 ZIP 项目上传、在线构建、开发者密钥、付费模型 SDK 或公开游戏发布。

## 用户流程

- 从原创“分支故事”或“轻量小游戏”模板开始，也可新建空白文件。
- 填写名称和简介，修改 HTML 源码，再点击“运行游戏”。修改源码后点击“重新运行”，不会每次输入都重启试玩。
- 已注册账号点击“保存”，写入自己的 D1 私人作品库。游客可先编写和试玩，登录后保存；游客草稿不会自动迁入其他账号。
- HTML 文件导入会创建独立副本；JSON 备份包含名称、简介和完整源码，也按新编号导入。导出 HTML 可以在本地自行使用。
- 未保存内容在当前浏览器、当前账号保留恢复副本。`new` 入口存在旧恢复副本时先恢复旧稿，避免初始化模板覆盖。切换未保存稿件前会提示；确认创建或导入新稿会替换该账号的单份浏览器恢复副本，应先保存或导出。

## 数据与一致性

`0034_creator_games.sql` 添加 `creator_games`，以 `(user_id,id)` 为主键。源码 UTF-8 最多 256 KiB；名称最多 120 字符，简介最多 4,000 字符。请求和 JSON 备份最多 2 MiB，以容纳 JSON 转义，但源码大小仍独立校验。

服务端 `/v1/games` 要求真实已登录且非游客的身份。创建、保存和删除正文必须携带当前 `accountId`；来源验证由现有认证路由执行。按所有者读写，不把其他账号的冲突快照返回给请求者。

创建使用独立 ID，重复创建返回 409 和当前账号快照。更新、删除用 `version` 做 D1 CAS；修改语句和随后读取放在同一 `DB.batch` 中。两页同时保存只允许一方更新，另一方保留编辑器内容，可导出、另存副本或明确加载云端版本。丢失保存回执后重试，仅当已认证云端快照与本次提交全部字段相同，才确认先前保存；修改后的稿件保持冲突。

客户端请求带 `credentials: same-origin`、`cache: no-store`、取消信号和 30 秒截止。没有自动重发写入。账号切换时整个编辑器按账号重挂，取消旧请求、丢弃旧预览，避免旧回包和旧稿写入新账号的恢复键。保存回执确认账号、游戏 ID 和源码内容；不匹配不会将当前稿件标成已保存。

## 试玩隔离

`iframe` 使用 `sandbox="allow-scripts"`，**不添加 `allow-same-origin`**，也不开放表单、弹窗、下载、顶层导航、摄像头或麦克风。最先插入的 CSP 仅允许内联脚本、内联样式和 data 图片/音频，不允许接口请求、外部脚本、字体、嵌套页面、插件、Worker、表单提交和自定义 base。后续导入的宽松 CSP 不能解除这份限制。

页面不向 iframe 注入叙梦账号、钱包、角色内容、API Key 或 `postMessage` 业务桥。导入源码不经 `eval` 或父文档 `innerHTML` 执行。沙箱不是全面的 HTML 净化器，也不承诺阻止所有 iframe 自身导航；其核心保证是试玩保持不透明来源，无法直接读取父页面 Cookie、localStorage 或 DOM。导出 HTML 是原始源码，脱离叙梦沙箱后运行时由使用者自行决定。

## 检查与交接

修改文件：`src/lib/xumeng-games.ts`、`xumeng-games-client.ts`、`src/components/dzmm/game-studio.tsx` 与对应 CSS、`cloudflare/dzmm/src/games.ts` 和 0034 迁移。根 agent 负责真实路由接入、统一创作首页和发布。

独立检查：

```sh
node --import tsx --test src/lib/xumeng-games.test.mts src/lib/xumeng-games-client.test.mts
cd cloudflare/dzmm
node --test test/games.test.mjs
```

共享逻辑包含原创模板的分支、两个结局和重新开始规则检查；这属于本地规则证据，不能替代真实浏览器试玩。后端测试使用隔离真实认证路由、Miniflare D1、真实迁移与临时注册账号，结束 dispose；无外部模型、公开投稿、钱包变更或付费媒体请求。UI、手机、正式 HTTP、正式有身份保存和生产迁移验收由本轮根 agent 的证据记录为准。

视觉安排：沿用叙梦黑色主题，以作品列表、源码和试玩构成工作面，不使用营销首屏。名称与保存状态作为一级信息，模板和私人作品作为二级操作，预览在桌面右侧、窄屏下方。仅保留保存/试玩的短反馈、列表悬停和轻微进入过渡；系统减少动态时关闭过渡。
