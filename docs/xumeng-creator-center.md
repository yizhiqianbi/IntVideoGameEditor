# 叙梦创作中心

入口 `https://xumengchat.top/#studio`。本轮根据 DZMM 公开创作中心实际浏览，统一角色、小说/故事、游戏和团本入口；使用叙梦既有深色主题。DZMM 游戏内部因游客 VIP1 门槛未能查看，其保存、开发者密钥、云端开发和发布行为未验收。不能将菜单观察当作实现同等后台能力的证据。

## 创作者流程

- 工作台：四类实际创建入口；本人作品按类型和标题/简介查找。私人角色来自账号草稿，小说、游戏、团本读取对应私人 API。一个目录读取失败显示明确错误，其他类型仍可使用。
- 角色与投稿：既有专业/快速角色编辑器、JSON 导入导出、开场、世界书、作者备注、声优与私人保存/试聊/审核继续复用。投稿管理新增所有投稿和撤回/下架归档，状态筛选在服务端完成再分页。已批准旧版本仍在线时可同时出现在“已发布”和新版本“待审核”等视图。
- 小说/故事：既有章节、大纲、人物、AI 预览和恢复副本继续复用。支持 `#novels/new/novel`、`#novels/new/story`、`#novels/<id>`；保存回执替换地址而不卸载编辑器，未插入的 AI 预览不会被路由更新清空。
- 游戏：`#studio/games`；私人单文件 HTML/CSS/JS 项目、两个原创模板、源码编辑、HTML/JSON 导入、备份/HTML 导出、独立沙箱试玩、云端保存与版本冲突保稿。参见 [游戏说明](xumeng-game-creation.md)。当前不是 ZIP 项目托管、云端终端或可接账号/钱包的开发者 SDK；没有公开游戏目录与公开发布。
- 团本：`#studio/scenarios`；创建剧本，设定开场、世界、目标、角色位、阶段、DM 提示词和隐藏笔记；保存并开房，生成私密邀请链接，受邀注册用户选角色加入；主持开始，参与者发言/行动，主持叙事和阶段推进。实际权限和角色位由后端管理。邀请仅公开简介与选角资料；主持笔记、DM 提示词与角色秘密只返回主持。房间冻结保存时剧本，后续改稿不改变已开房间。详情见 [团本说明](xumeng-scenario-studio.md)。

## AI DM 与费用

主持点击“生成叙事草稿”才调用默认 Grok，输出上限 1200 token；复用现有模型、速率限制、真实用量结算/预留和失败释放路径，保持成本三倍的现有政策。保存、开房、真人发言和试玩不调用模型。生成先在主持私有页面预览，手动发布后参与者可见；房间阶段/版本变化时需主持核对旧草稿，不能把旧事件当作当前结果。

`POST /api/dzmm/scenario` 仅接受房间编号和生成 UUID。Web Worker 用当前 Cookie 读取后台房间，验证本人为主持且房间未结束；上下文由服务端冻结剧本和最近 24 条事件生成，事件正文各最多末 2000 字。模型不接收客户端任意传入的隐藏资料或伪造历史。没有宣称全场长期记忆、自动 DM 回合调度或完整竞品 Agent 建设能力。

## 关键代码与延续工作

- UI：`creator-center.tsx`、`game-studio.tsx`、`scenario-studio.tsx`；主路由集成 `tavern-app.tsx`。
- 私人游戏 API：`cloudflare/dzmm/src/games.ts`；D1 迁移 0034。
- 团本 API：`cloudflare/dzmm/src/scenarios.ts`；D1 迁移 0035。剧本 CRUD、房间、成员、事件；版本 CAS、角色占用唯一索引、消息请求编号去重。
- AI 上下文：`src/lib/xumeng-scenario-handler.ts`；真实模型网关 `cloudflare/dzmm-web/src/worker.ts`。
- 同一编辑器内部新建、打开、保存、开房和返回库都要更新真实地址，但保持组件内草稿和预览不被重新挂载清空。跨页面由 dirty/busy 保护，切账号则重置私人初始路由。
- 现阶段游戏和团本是私人创作与邀请使用；公开上架需要另做内容快照、审核、下架、公开发现和验收，不把私人保存伪装为公开发布。

证据目录：`output/xumeng/iteration/creator-center-20261010/`，以最终 round.json 记录的已通过范围为准；源码检查、隔离 API、真实 UI、生产资源和付费模型输出是不同证据层次。
