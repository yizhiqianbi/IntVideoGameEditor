## Accounts across origins

`xumengchat.top`, `workers.dev`, and `http://127.0.0.1:3010` each have their own browser cookie and localStorage. None can automatically inherit another origin's guest identity.

To continue with the original local guest's characters and chats, register that guest from the local profile page, wait for synchronization, then log in with the same email on this site. Registration preserves the user ID and access to its D1 records and private R2 covers. Existing registered users can log in directly. The full backup export has no corresponding cross-origin full-state import UI; individual role/conversation imports do not transfer guest credentials or private cover ownership.

## Build and deploy

Run from `cloudflare/dzmm-web` with the Cloudflare account that owns the existing backend:

```sh
npm ci
npm run check
npm run test:web
npm run deploy:dry-run
# If the root project's local model configuration is already set:
npm run secrets:sync
npm run deploy
```

`secrets:sync` passes only the selected local model key to Wrangler through standard input. It does not create a secret file or upload `.env.local`. Alternatively, enter a key at `npx wrangler secret put DZMM_API_KEY --config wrangler.jsonc`. Ordinary redeployments reuse the existing Secret. Keep provider keys out of browser variables and plaintext configuration.

电话与视频是两条独立链路：电话入口使用 MiniCPM-o 4.5 Realtime 的音频 WebSocket，视频入口仍使用 Vidu S2 + RTC。电话中继读取 `MINICPM_REALTIME_URL` 与 `MINICPM_API_KEY`，密钥只作为 Worker Secret 保存；可配置 ModelBest 的托管 Gateway，也可指向已有 MiniCPM 自托管服务的受保护 WSS relay。自托管服务若仍只监听 `127.0.0.1:8016`，Worker 无法直接访问，需要先部署 relay。

配置托管实时 Gateway 时执行 `npx wrangler secret put MINICPM_API_KEY --config wrangler.jsonc`，再部署 Worker。没有这个 Secret 时，电话状态会明确显示未配置，不会回退成伪造的音频或误用 Vidu。浏览器只连接 `/api/phone/ws`，不会接触上游密钥。

`wrangler.jsonc` deploys the `dzmm-web` Worker, static assets, `BACKEND` Service Binding, and `CHAT_RATE_LIMITER`. It runs no D1 migrations. The default public address is the Worker's `workers.dev` hostname.

`npm run dev` serves the Vite page on port 5174, and `npm run preview` serves the build on port 4174. These page-only servers do not provide the account or chat APIs. `npm run dev:worker` serves the Worker locally on port 8791 and needs the backend service connected; use the deployed site for the complete current setup.

Saving a draft and submitting for publication are separate actions. Registered users submit a normalized snapshot to the backend; Super reviews full character fields and protected image previews before approving or returning a reason. Only approved revisions enter the public catalog and author works under a new `published-UUID` ID. Updating a draft or submitting a pending revision does not overwrite the online approved version. The publication's expected version prevents stale/multiple-device writes, and browser mutations bind their account ID to the session.
